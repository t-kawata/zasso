# RFC_006: 数学的定式化・収束制御（conver-core）

## Abstract

本RFCは、conver オーケストレータの数学的基盤を規定する。開発空間の定義、
RFCツリーの形式化、乖離関数Δの計算、観測ベクトルo_rの記録、収束ループ制御、
人間介入モデルの6領域を形式的に定義する。

本RFCで定義される数学的モデルは `conver-core` crate（RFC_002）内の `deviation.rs`、
`observation.rs`、`convergence.rs` に実装される。本RFCは実装から数学的意味を
分離し、仕様としての正確性を担保する。

親RFC: [RFC_ROOT.md](crates/conver/RFC_ROOT.md)（conver: 決定論的 Rust オーケストレータ）
実装crate: `conver-core`（crates/conver/rfc-002-core/）
対応モジュール: `deviation.rs` / `observation.rs` / `convergence.rs`

```text
conver-core/
  deviation.rs      ← 乖離関数Δ、OmissionKind、DeviationCalculator
  observation.rs    ← 観測ベクトルo_r、ObservationRecorder
  convergence.rs    ← 収束ループ制御、ConvergenceController
```

## Motivation

conver の「自己収束」は、比喩ではなく数学的に定義されなければならない。
「完成したかどうか」を主観ではなく形式的基準で判定するためには、以下の
数学的枠組みが必要である：

1. **開発空間の定義**: 仕様空間 S と実装空間 I を分離し、開発状態 d ∈ D を
   形式化する。これにより「仕様と実装の乖離」を数学的に扱える。
2. **乖離関数 Δ**: 開発状態 d から非負実数への写像 Δ: D → R_{\ge 0} を定義し、
   Δ=0 を唯一の完成条件とする。
3. **観測ベクトル o_r**: 各ループ反復 r の状態を11次元ベクトルで記録し、
   収束の時系列を観測可能にする。
4. **収束ループ制御**: Δ>0 の場合に omissions の種類に応じたフィードバック先を
   決定し、ループ上限（デフォルト3）を課す。
5. **人間介入モデル**: 制御系外部からの介入を H(d, u) → d' として形式化する。

```rust
// 数学的モデルの使用イメージ
let d = DevelopmentState { specification, implementation };
let delta = deviation_calculator.calculate(&d.omissions());
if delta == 0.0 {
    state.transition(WorkflowState::Done)?;
} else {
    let phase = convergence.determine_feedback_phase(&d.omissions());
    state.force_transition(phase);
    round_manager.start_next_round()?;
    observation.append(&ObservationVector::from(&d, &delta))?;
}
```

## Design

### 1. 開発空間

#### 1.1 定義

開発空間は仕様空間と実装空間の直積として定義する。

\[
\mathcal{D} = \mathcal{S} \times \mathcal{I}
\]

- \(\mathcal{S}\): 仕様空間。頂点RFC、分解RFC群（RFC_XXX.md）、RFC_TREE、
  チケット仕様群（Tickets.json）から成る。
- \(\mathcal{I}\): 実装空間。実ソースコード、テスト、ビルド生成物、
  STUB台帳（[::STUB::]マーカー）、レビュー結果から成る。

任意の時刻 t における開発状態は \(d_t = (s_t, i_t) \in \mathcal{D}\) と表される。

```rust
/// 開発空間の状態。
pub struct DevelopmentState {
    /// 現時点の仕様。
    pub specification: SpecificationSnapshot,
    /// 現時点の実装。
    pub implementation: ImplementationSnapshot,
    /// 最終更新時刻。
    pub timestamp: chrono::DateTime<chrono::Utc>,
}

/// 仕様のスナップショット。
pub struct SpecificationSnapshot {
    /// 頂点RFCの内容。
    pub root_rfc: String,
    /// 分解RFC群の内容（id → 本文）。
    pub rfc_files: std::collections::HashMap<String, String>,
    /// RFC_TREE.json の内容。
    pub rfc_tree: String,
    /// 全チケット仕様。
    pub tickets: Vec<TicketRecord>,
}

/// 実装のスナップショット。
pub struct ImplementationSnapshot {
    /// 実装コード全体のハッシュ。
    pub code_hash: String,
    /// 検出されたSTUBの一覧。
    pub stubs: Vec<StubEntry>,
    /// 最新のレビュー結果。
    pub review_results: Vec<ReviewResult>,
}
```

#### 1.2 開発空間上での操作

開発空間上の状態遷移は以下の操作によって生じる：

| 操作 | 影響 | 例 |
|------|------|----|
| 仕様変更 | s → s' | RFC修正、チケット追加 |
| 実装変更 | i → i' | コード追加、STUB解決 |
| 両方変更 | (s,i) → (s',i') | チケット完了によるRFC+コード同時変更 |
| 人間介入 | d → H(d,u) | オーバーライド、ロールバック |

### 2. RFCツリーの形式化

RFCツリーは単純木ではなく、親子関係と依存関係を併せ持つ有向非巡回グラフである。

\[
T = (V, E_h, E_d, \sigma)
\]

| 記号 | 意味 | 型 |
|------|------|------|
| \(V\) | RFCノード集合 | `Vec<RfcNode>` |
| \(E_h \subseteq V \times V\) | 階層辺（parent-child） | `EdgeKind::Hierarchy` |
| \(E_d \subseteq V \times V\) | 依存辺（depends-on） | `EdgeKind::Depends` |
| \(\sigma: V \to M\) | ノードメタデータ関数 | `RfcNode` 構造体 |

各ノード \(v \in V\) に対し、\(\sigma(v)\) は以下を含む：

```rust
pub struct RfcNodeMeta {
    pub id: String,                    // 一意ID
    pub title: String,                // タイトル
    pub scope: String,                // スコープ定義
    pub acceptance_criteria: Vec<String>, // 受入条件
    pub estimated_ticket_count: u32,  // 推定チケット数
    pub status: RfcNodeStatus,        // draft/pending/active/done
    pub parents: Vec<String>,         // 親ノードID列
    pub children: Vec<String>,        // 子ノードID列
    pub depends_on: Vec<String>,      // 依存先ノードID列
    pub required_by: Vec<String>,     // 被依存ノードID列
    pub verification_boundary: String, // 検証境界
    pub reusability_boundary: String,  // 再利用境界
}
```

DAG条件: \((V, E_h \cup E_d)\) に閉路が存在しないこと。実装では petgraph の
`is_cyclic_digraph` で検証する（RFC_002 tree.rs）。

### 3. 乖離関数 Δ

#### 3.1 定義

仕様と実装の収束状況を定量化するため、乖離関数を導入する。

\[
\Delta : \mathcal{S} \times \mathcal{I} \to \mathbb{R}_{\geq 0}
\]

最小構成では以下の線形結合として定義する：

\[
\Delta(s,i) = \alpha M(s,i) + \beta C(s,i) + \gamma U(s,i) + \delta X(s,i)
\]

#### 3.2 4分類の定義

| 記号 | 分類 | 内容 | 検出方法 |
|------|------|------|---------|
| M | Implementation Missing | RFCに記述された機能が実装コードに存在しない | Claude Code（LLM） |
| C | Implementation Contradiction | 実装の挙動がRFCの記述と矛盾する | Claude Code（LLM） |
| U | Specification Deficiency | 実装中に顕在化したがRFCに未記述の項目 | Claude Code（LLM） |
| X | Structural Inconsistency | RFC_TREE.json と RFC_XXX.md 群の親子・依存・状態が不一致 | プログラム（機械的） |

#### 3.3 重みパラメータ

| パラメータ | デフォルト値 | 意味 |
|-----------|------------|------|
| α (alpha) | 2.0 | Structural Inconsistency — 構造崩壊リスク（最大） |
| β (beta) | 2.0 | Implementation Contradiction — 誤動作リスク（最大） |
| γ (gamma) | 1.0 | Specification Deficiency — 記述漏れ（中程度） |
| δ (delta) | 1.0 | Implementation Missing — 未実装（最小） |

重みの設計意図：
- X と C を高く設定（2.0）している理由は、構造不整合と実装矛盾がシステムの
  信頼性を直接損なうためである。これらは発見次第即座に修正すべき乖離。
- U と M は 1.0 としており、発見は重要だが X や C ほどクリティカルではない
  という判断を反映している。

全重みは `settings.json` の `deviation` セクションでユーザーが上書き可能。
デフォルト値はあくまで初期値である。

```rust
/// 乖離スコア。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DeviationScore {
    /// 大域乖離スコア（Δ = αM + βC + γU + δX）。
    pub delta: f64,
    /// 各成分の内訳。
    pub components: DeviationComponents,
    /// RFCノード別の乖離ベクトル。
    pub per_node: Vec<(String, f64)>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct DeviationComponents {
    pub m: usize,  // Implementation Missing 件数
    pub c: usize,  // Implementation Contradiction 件数
    pub u: usize,  // Specification Deficiency 件数
    pub x: usize,  // Structural Inconsistency 件数
}

impl DeviationScore {
    /// ゼロスコア（Δ = 0）。
    pub fn zero() -> Self {
        Self {
            delta: 0.0,
            components: DeviationComponents { m: 0, c: 0, u: 0, x: 0 },
            per_node: Vec::new(),
        }
    }

    /// Δ = 0 か（収束完了）。
    pub fn is_converged(&self) -> bool {
        self.delta == 0.0
    }

    /// 改善方向（前回のスコアから改善したか）。
    pub fn improved_since(&self, previous: &DeviationScore) -> bool {
        self.delta < previous.delta
    }
}
```

#### 3.4 計算アルゴリズム

```rust
/// 乖離関数 Δ の計算機。
pub struct DeviationCalculator {
    pub alpha: f64,
    pub beta: f64,
    pub gamma: f64,
    pub delta: f64,
}

impl DeviationCalculator {
    pub fn from_settings(settings: &DeviationSettings) -> Self {
        Self {
            alpha: settings.alpha,
            beta: settings.beta,
            gamma: settings.gamma,
            delta: settings.delta,
        }
    }

    /// Δ = αM + βC + γU + δX を計算する。
    ///
    /// # 引数
    /// - `omissions`: 現在の全omissionsデータ
    ///
    /// # 戻り値
    /// 大域乖離スコアと各成分の内訳。
    pub fn calculate(&self, omissions: &OmissionsLedger) -> DeviationScore {
        let m = omissions.count_by_kind(OmissionKind::ImplementationMissing);
        let c = omissions.count_by_kind(OmissionKind::ImplementationContradiction);
        let u = omissions.count_by_kind(OmissionKind::SpecificationDeficiency);
        let x = omissions.count_by_kind(OmissionKind::StructuralInconsistency);

        let delta = self.alpha * x as f64
                  + self.beta * c as f64
                  + self.gamma * u as f64
                  + self.delta * m as f64;

        DeviationScore {
            delta,
            components: DeviationComponents { m, c, u, x },
            per_node: Vec::new(), // 呼出し元でRFCノード別に集計して設定
        }
    }

    /// RFCノード別の乖離ベクトルも含めて計算する。
    pub fn calculate_per_node(
        &self,
        omissions: &OmissionsLedger,
    ) -> DeviationScore {
        let mut score = self.calculate(omissions);

        // RFCノード別に集計
        let mut per_node: std::collections::HashMap<String, f64> =
            std::collections::HashMap::new();
        for entry in &omissions.omissions {
            let weight = match entry.kind {
                OmissionKind::ImplementationMissing => self.delta,
                OmissionKind::ImplementationContradiction => self.beta,
                OmissionKind::SpecificationDeficiency => self.gamma,
                OmissionKind::StructuralInconsistency => self.alpha,
            };
            *per_node.entry(entry.rfc_node_id.clone()).or_insert(0.0) += weight;
        }

        score.per_node = per_node.into_iter().collect();
        score
    }
}
```

### 4. 観測ベクトル o_r

#### 4.1 定義

各第一層ループ反復 \(r\) に対して観測ベクトルを記録する。

\[
\mathbf{o}_r = (r, |V_r|, |K_r|, \Delta_r, \vec{\Delta}_r, \tau_r, \rho_r, \eta_r)
\]

| 成分 | 記号 | 型 | 意味 |
|------|------|------|------|
| ループ回数 | \(r\) | u32 | 何回目のループか |
| RFCノード数 | \(|V_r|\) | u32 | RFCツリーのノード総数 |
| 全チケット数 | \(|K_r|\) | u32 | 全RFCに属するチケット総数 |
| 大域乖離スコア | \(\Delta_r\) | f64 | 乖離関数の値 |
| ノード別乖離 | \(\vec{\Delta}_r\) | Vec<(String,f64)> | RFCノードごとの乖離 |
| ラウンド所要時間 | \(\tau_r\) | u64 | このループにかかった秒数 |
| 負債指標 | \(\rho_r\) | f64 | STUB密度 + レビュー失敗率の複合指標 |
| 介入イベント | \(\eta_r\) | Vec<String> | 人間介入イベントの時系列 |

```rust
/// 観測ベクトル o_r（11フィールド）。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ObservationVector {
    /// r: ループ回数。
    pub r: u32,
    /// Δ_r: 大域乖離スコア。
    pub delta: f64,
    /// M: Implementation Missing 件数。
    pub m: usize,
    /// C: Implementation Contradiction 件数。
    pub c: usize,
    /// U: Specification Deficiency 件数。
    pub u: usize,
    /// X: Structural Inconsistency 件数。
    pub x: usize,
    /// |V_r|: RFCノード数。
    pub v_count: u32,
    /// |K_r|: 全チケット数。
    pub k_count: u32,
    /// τ_r: ラウンド所要時間（秒）。
    pub duration_secs: u64,
    /// ρ_r: 負債指標（0.0〜1.0）。
    pub debt_index: f64,
    /// η_r: 人間介入イベント列。
    pub interventions: Vec<String>,
}

impl ObservationVector {
    /// 観測ベクトルを構成する。
    pub fn new(
        round: u32,
        deviation: &DeviationScore,
        rfc_count: u32,
        ticket_count: u32,
        duration_secs: u64,
        debt_index: f64,
        interventions: Vec<String>,
    ) -> Self {
        Self {
            r: round,
            delta: deviation.delta,
            m: deviation.components.m,
            c: deviation.components.c,
            u: deviation.components.u,
            x: deviation.components.x,
            v_count: rfc_count,
            k_count: ticket_count,
            duration_secs,
            debt_index,
            interventions,
        }
    }
}
```

#### 4.2 記録と保存

観測ベクトルは `round_log.jsonl` に append-only で保存される。

```rust
/// 観測ベクトル記録器。
pub struct ObservationRecorder;

impl ObservationRecorder {
    /// 観測ベクトルを round_log.jsonl に追記する。
    ///
    /// 保存は機械的に行われ、Claude CodeのLLM呼出しは誘発しない。
    pub fn append(
        &self,
        storage: &mut dyn StorageBackend,
        obs: &ObservationVector,
    ) -> Result<(), StorageError> {
        let line = serde_json::to_string(obs)?;
        storage.append("round_log.jsonl", line.as_bytes())?;
        Ok(())
    }

    /// 最新の観測ベクトルを読み込む。
    pub fn latest(
        &self,
        storage: &dyn StorageBackend,
    ) -> Result<Option<ObservationVector>, StorageError> {
        let content = storage.read_to_string("round_log.jsonl")?;
        let last_line = content.lines().last().map(|s| s.to_string());
        match last_line {
            Some(line) => {
                let obs: ObservationVector = serde_json::from_str(&line)?;
                Ok(Some(obs))
            }
            None => Ok(None),
        }
    }

    /// 全観測ベクトルを時系列順に取得する。
    pub fn all(
        &self,
        storage: &dyn StorageBackend,
    ) -> Result<Vec<ObservationVector>, StorageError> {
        let content = storage.read_to_string("round_log.jsonl")?;
        let mut observations = Vec::new();
        for line in content.lines() {
            if let Ok(obs) = serde_json::from_str::<ObservationVector>(line) {
                observations.push(obs);
            }
        }
        Ok(observations)
    }
}
```

### 5. 収束ループ制御

#### 5.1 定義

収束ループは、乖離が検出された場合に仕様空間と実装空間の距離を縮めるための
反復プロセスである。

\[
\text{converge}(d_r) = \begin{cases}
d_{r+1} = \text{feedback}(d_r, \text{phase}(\Delta(d_r))) & \text{if } \Delta(d_r) > 0 \\
\text{done} & \text{if } \Delta(d_r) = 0
\end{cases}
\]

#### 5.2 フィードバック先の決定

Δ > 0 の場合、omissions の種類に応じてフィードバック先が異なる。

```rust
/// 収束ループ制御。
pub struct ConvergenceController {
    round_manager: RoundManager,
    deviation_calculator: DeviationCalculator,
    max_rounds: u32,
}

impl ConvergenceController {
    pub fn new(max_rounds: u32, deviation_settings: &DeviationSettings) -> Self {
        Self {
            round_manager: RoundManager::new(max_rounds),
            deviation_calculator: DeviationCalculator::from_settings(deviation_settings),
            max_rounds,
        }
    }

    /// omissions の種類に応じてフィードバック先の WorkflowState を決定する。
    ///
    /// | 検出された乖離 | フィードバック先 | 意味 |
    /// |---------------|----------------|------|
    /// | X (Structural Inconsistency) | ChecklistPending | Phase 2: RFCツリー再構成 |
    /// | U (Specification Deficiency) | Grilling | Phase 1: 頂点RFC改訂 |
    /// | M (Implementation Missing) | ChecklistApproved | Phase 4: チケット再実行 |
    /// | C (Implementation Contradiction) | ChecklistApproved | Phase 4: チケット再実行 |
    /// | なし (Δ=0) | None | 完了 |
    pub fn determine_feedback_phase(
        &self,
        omissions: &OmissionsLedger,
    ) -> Option<WorkflowState> {
        // 優先順位: X > U > M,C（複数種類が同時に存在した場合、
        // より上位のPhaseから再実行する）

        // X: 構造不整合 — 最優先（RFCツリー自体が壊れている）
        if omissions.has_kind(OmissionKind::StructuralInconsistency) {
            return Some(WorkflowState::ChecklistPending);
        }
        // U: 仕様不足 — RFC改訂が必要
        if omissions.has_kind(OmissionKind::SpecificationDeficiency) {
            return Some(WorkflowState::Grilling);
        }
        // M/C: 実装不足・矛盾 — チケット再実行
        if omissions.has_kind(OmissionKind::ImplementationMissing)
            || omissions.has_kind(OmissionKind::ImplementationContradiction)
        {
            return Some(WorkflowState::ChecklistApproved);
        }
        None
    }

    /// 1ループ分の収束処理を実行する。
    ///
    /// # 引数
    /// - `omissions`: 現時点の全omissions
    /// - `state`: 大域状態（変更可能参照、フィードバック先に更新される）
    ///
    /// # 戻り値
    /// - `Ok(ConvergenceResult::Converged)`: Δ=0、収束完了
    /// - `Ok(ConvergenceResult::Feedback { .. })`: Δ>0、フィードバック実行
    /// - `Err(ConvergenceError::LoopLimitExceeded)`: ループ上限超過
    pub fn converge_round(
        &mut self,
        omissions: &OmissionsLedger,
        state: &mut WorkflowState,
    ) -> Result<ConvergenceResult, ConvergenceError> {
        let score = self.deviation_calculator.calculate(omissions);

        if score.is_converged() {
            *state = WorkflowState::Done;
            return Ok(ConvergenceResult::Converged(score));
        }

        // ループカウント増加（上限チェック含む）
        let round = self.round_manager.start_next_round()?;

        // フィードバック先決定
        let next_phase = self.determine_feedback_phase(omissions)
            .unwrap_or(WorkflowState::Grilling);

        *state = next_phase;

        Ok(ConvergenceResult::Feedback {
            round,
            score,
            feedback_to: next_phase,
        })
    }
}

/// 収束ループの実行結果。
#[derive(Debug)]
pub enum ConvergenceResult {
    /// Δ=0、収束完了。
    Converged(DeviationScore),
    /// フィードバック実行（指定Phaseに戻る）。
    Feedback {
        round: u32,
        score: DeviationScore,
        feedback_to: WorkflowState,
    },
}
```

#### 5.3 ループ状態図

```text
Δ = 0 ──→ Done（収束完了）
   ↑
   │
[converge_round]
   │
   ├── X (Structural) → ChecklistPending (Phase 2)
   ├── U (Specification) → Grilling (Phase 1)
   ├── M/C (Missing/Contradiction) → ChecklistApproved (Phase 4)
   │
   └── Δ = 0 判定 → Done
```

#### 5.4 ループ上限と設定

```rust
/// ループ管理。
pub struct RoundManager {
    current_round: u32,
    max_rounds: u32,  // settings.report.convergence_loop_limit から設定
}

impl RoundManager {
    pub fn new(max_rounds: u32) -> Self {
        Self { current_round: 0, max_rounds }
    }

    /// 次のループ反復を開始する。
    /// 上限（デフォルト3）を超えている場合は Err を返す。
    pub fn start_next_round(&mut self) -> Result<u32, ConvergenceError> {
        if self.current_round >= self.max_rounds {
            return Err(ConvergenceError::LoopLimitExceeded {
                current: self.current_round,
                max: self.max_rounds,
            });
        }
        self.current_round += 1;
        Ok(self.current_round)
    }

    pub fn current_round(&self) -> u32 { self.current_round }
}

#[derive(Debug, thiserror::Error)]
pub enum ConvergenceError {
    #[error("ループ上限超過: {current}/{max}")]
    LoopLimitExceeded { current: u32, max: u32 },
}
```

### 7. 完了条件

以下の全条件が満たされた場合のみ、開発状態は形式的収束点に達したとみなされる。

```rust
/// 形式的完了条件の検証。
pub struct CompletionVerifier;

impl CompletionVerifier {
    /// 全完了条件を検証する。
    ///
    /// 以下の6条件の論理積が必要：
    /// 1. RFC_TREE.json と全 RFC_XXX.md の整合性が成立
    /// 2. 全チケットDAGが完了状態
    /// 3. 未解決STUBがゼロ、または明示的 override 下にある
    /// 4. omission ledger が空
    /// 5. 乖離関数 Δ = 0
    /// 6. 強制停止や暫定凍結が残っていない
    pub fn verify(
        &self,
        rfc_tree: &str,
        tickets: &[TicketDag],
        stub_count: usize,
        omissions: &OmissionsLedger,
        delta: f64,
        has_override: bool,
    ) -> Result<CompletionReport, CompletionError> {
        let mut failures = Vec::new();

        // 条件1: RFC_TREE.json の整合性
        if rfc_tree.is_empty() {
            failures.push("RFC_TREE.json が空".to_string());
        }

        // 条件2: 全チケット完了
        let unfinished: Vec<&str> = tickets.iter()
            .flat_map(|dag| dag.tickets.iter())
            .filter(|t| t.status != TicketStatus::Done)
            .map(|t| t.id.as_str())
            .collect();
        if !unfinished.is_empty() {
            failures.push(format!(
                "未完了チケット: {}", unfinished.join(", ")
            ));
        }

        // 条件3: STUB
        if stub_count > 0 && !has_override {
            failures.push(format!("未解決STUB: {stub_count}件"));
        }

        // 条件4: omissions空
        if !omissions.is_empty() {
            failures.push(format!("未解決omissions: {}件", omissions.omissions.len()));
        }

        // 条件5: Δ = 0
        if delta > 0.0 {
            failures.push(format!("Δ = {delta} > 0"));
        }

        // 条件6: 凍結・停止
        // （フラグが別途管理される）

        if failures.is_empty() {
            Ok(CompletionReport { converged: true, delta })
        } else {
            Err(CompletionError::NotConverged(failures))
        }
    }
}

#[derive(Debug)]
pub struct CompletionReport {
    pub converged: bool,
    pub delta: f64,
}

#[derive(Debug, thiserror::Error)]
pub enum CompletionError {
    #[error("収束未完了:\n{0}")]
    NotConverged(Vec<String>),
}
```

### 8. Omissions Ledger の数学的構造

```rust
/// omissions ledger のエントリ。
/// 各エントリは乖離関数Δの1成分に対応する。
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct OmissionEntry {
    /// 乖離の分類（M/C/U/X）。
    pub kind: OmissionKind,
    /// 該当RFCノード。
    pub rfc_node_id: String,
    /// 関連チケット（ある場合）。
    pub ticket_id: Option<String>,

    pub description: String,
    /// コード位置（ファイル:行）。
    pub code_location: Option<String>,
    /// 関連STUB。
    pub stub_id: Option<String>,
    /// 重要度（critical / major / minor）。
    pub severity: String,
    /// 検出日時。
    pub detected_at: chrono::DateTime<chrono::Utc>,
}

/// 乖離の4分類。
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq)]
pub enum OmissionKind {
    /// RFC記述あり未実装 → δM
    ImplementationMissing,
    /// 実装がRFCと矛盾 → βC
    ImplementationContradiction,
    /// 実装から見つかったRFC抜け → γU
    SpecificationDeficiency,
    /// RFC_TREE.jsonとRFC_XXX.mdの不整合 → αX
    StructuralInconsistency,
}
```

### D. 本RFCの完了条件

1. `DeviationCalculator` が Δ = αM + βC + γU + δX を正しく計算すること
2. デフォルト重みが α=2, β=2, γ=1, δ=1 であること
3. `DeviationScore::is_converged()` が Δ=0 で true を返すこと
4. 観測ベクトル o_r が11フィールド全てを含むこと
5. `ConvergenceController::determine_feedback_phase()` が4分類それぞれに
   正しいフィードバック先を返すこと（X→ChecklistPending, U→Grilling, M/C→ChecklistApproved）
6. 複数種類の乖離が同時に存在する場合、優先順位（X > U > M,C）に従うこと
7. `RoundManager` がループ上限超過を `ConvergenceError` として報告すること
8. `CompletionVerifier` が6条件すべてを検証すること
9. `Intervention::summary()` が種類と理由を含む要約を生成すること
10. `DeviationScore::improved_since()` が正しい改善判定を行うこと
11. `cargo test -p conver-core`（本RFCの該当モジュール）が全テストパスすること
12. 親RFC（RFC_ROOT.md）の数学的定式化および収束制御の設計判断と矛盾しないこと
