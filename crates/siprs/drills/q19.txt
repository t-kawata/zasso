Q9c（Q9 の子決定）: docker 可用性ゲートのスキップ意味論を確定します。

【背景と理由】あなたの指示「テストコードには docker が使用可能状態かをチェックし、使用可能な場合のみに実行するテストであることを必要とする」を具体化します。docker が使用不能な場合のテストの振る舞いを確定する必要があります。選択肢は、明示ログ付きスキップ（成功扱い）、失敗（必須ゲート）、コンパイル単位での除外の 3 通りです。CI では docker が常に使用可能なため実質ゲートになりますが、ローカル開発（Docker Desktop 停止中）での make test の挙動が問題です。

A) docker 不可時は `[SKIPPED: docker unavailable]` を明示ログ出力してテストをスキップ（成功扱い）。CI では docker があるため常に実行され実質ゲートになる
B) docker 不可時はテストを失敗させる（必須ゲートとして常に docker を要求）
C) docker 前提のテストを feature ゲートでコンパイルから除外し、docker 可用性チェック自体を不要にする

【推奨】A を推奨します。あなたの指示「docker が使用可能な場合のみに実行する」は A のスキップ意味論と一致し、ローカル開発を壊しません。CI では docker が常に使用可能なため実質的な必須ゲートとして機能します。選択肢 B は Docker Desktop 停止中のローカル make test を壊します。選択肢 C は実行時チェックを排除するため指示と矛盾します。
