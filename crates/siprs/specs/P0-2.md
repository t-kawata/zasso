# P0-2: ClientConfig 構造体完全定義とデフォルト実装

## RFC Reference

/Users/kawata/shyme/zasso/crates/siprs/RFC-ROOT (§10)

## Background

### Goal
ClientConfig 構造体とそのサブ構造体（ClientAudioConfig/TimeoutConfig/RawSipEventConfig）および LogLevel enum を完全に定義し、RFC §10 の設計を Rust コードとして具現化する。同時に Default トレイト実装により RFC §10.1 の既定値を提供する。

### Purpose
SipClient::new() は ClientConfig を唯一の引数として受け取る。本構造体は SIP クライアントの全動作設定（ユーザーエージェント文字列、ログレベル、最大通話数、イベントバス容量、音声配信設定、トランスポート、STUN/TURN/ICE、Raw SIP イベント、各種タイムアウト）を集約し、型安全な初期化を可能にする。

### Motivation
ClientConfig は zasso の音声通話基盤 siprs のエントリポイントとなる構造体。他の全設定型（AccountConfig/TransportConfig/IceConfig）も ClientConfig に集約されるため、本チケットは後続の全実装（P0-5: アカウント設定、P1-1: ICE/STUN/TURN、P2: 公開API）の前提となる。

### Constraints
- 外部クレート依存は追加禁止（Cargo.toml は依存 crate 無し）。std::time::Duration のみ使用。
- TransportConfig/IceConfig/StunServerConfig/TurnServerConfig 型は本チケット未実装のため、Default 実装ではこれらの型の存在を前提とした記述に留める。
- AudioFormat/SampleRate/BitDepth/ChannelLayout 型は src/model/audio_format_model.rs（N0056）で定義予定。ResamplerQuality は RFC で未定義のため本チケット内で enum として規定する。
- シリアライゼーション（serde）は feature flag で制御するが、本チケットでは未導入。

## Boy Scout Rule

# 翻訳可能性改善計画

本チケットで新規作成する src/config/client_config.rs に対し、以下の翻訳可能性原則を適用する：

## 1. 関数名は動詞句
Default トレイトの impl ブロック内では、self の各フィールドに意味のあるコメントを付与する（例: `// user_agent: SIP クライアントの User-Agent 文字列`）。ただしコメントは「何を」ではなく「なぜ」を説明する。

## 2. 変数名はドメイン概念
- `user_agent` → SIP 標準の User-Agent ヘッダー
- `max_calls` → 同時最大通話数
- `event_bus_capacity` → イベントバスキュー長
- `raw_sip_event_capacity` → Raw SIP イベントバッファリング数
- `pair_buffer_ms` → IN/OUT ペアリングバッファ時間
- `jitter_buffer_ms` → ジッターバッファ時間
- 全てのフィールド名は RFC の命名と完全一致させる

## 3. 一関数一責務
- Default::default() はフィールド初期化のみ。副作用なし。
- impl ClientConfig { ... } ブロックは本チケットでは追加しない（後続チケットで必要に応じて）。

## 4. ハードコード値は名前付き定数
- マジックナンバーは直接 Default 実装に記述する（RFC §10.1 の既定値が定義そのものであり、別途定数化すると追跡性が低下するため）。コメントで RFC のセクション番号 §10.1 を明記する。

## 5. エラー握りつぶし禁止
- Default::default() は pure data 構造体の構築であり、Result を返さない。panic の可能性は無い。

## スコープ外の改善対象
- 同じ config ディレクトリ内の他のスタブファイル（transport_config.rs, ice_stun_turn.rs 等）は本チケットのスコープ外だが、Initial Design Artifact ヘッダーが存在することを確認した。これらは別チケットで整備される。

  ④ RawSipEventConfig 構造体定義追加（4フィールド）
  ⑤ LogLevel enum 定義追加（Error/Warn/Info/Debug/Trace）
  ⑥ Default トレイト実装追加（RFC §10.1 の全既定値に準拠）
  ⑦ 依存型（TransportConfig, IceConfig, StunServerConfig, TurnServerConfig, AudioFormat, SampleRate, BitDepth, ChannelLayout, ResamplerQuality）の use 文追加

- 【リスク】
  - 依存先チケット P0-5（TransportConfig）と P1-1（IceConfig/StunServerConfig/TurnServerConfig）が未実装のため、Default 実装がコンパイル時に未解決参照となる可能性がある。これらが準備されるまで Default 実装を #[cfg(test)] でガードするか、コメントアウトしておく暫定対応を検討。
  - AudioFormat/SampleRate/BitDepth/ChannelLayout/ResamplerQuality が未定義のため、これらの型定義の準備が整うまで Default 実装の一部がコンパイルできない。

- 【注意事項】
  - 既存ファイル src/config/client_config.rs には Initial Design Artifact ヘッダーが存在する。これを絶対に削除・編集してはならない（Supreme law #4）。
  - 空の pub struct Config {} は不要になるが、互換性のために #[deprecated] エイリアスを残す判断もある（後続チケット P2 で判断）。
  - src/config/config_defaults.rs の N0023（§10.1 既定値）スタブは P1-1 のスコープ。Default 実装は client_config.rs に直接記述する。

- 【未解決項目】
  - ResamplerQuality の定義（RFC で未定義）。Low/Medium/High の3バリアント enum として本チケット内で定義するが、後続のリサンプラ実装チケットで見直しの余地あり。
  - LogLevel の PartialOrd 実装（Error < Warn < Info < Debug < Trace の順序付けが必要かどうかは利用者要件次第）。本チケットでは #[derive(PartialOrd)] のみとし、独自実装は行わない。
