# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

## Background

N0041 defines two-layer codec: explicit user specification vs auto mode (Opus=255, PCMU=254). N0042 defines SrtpPolicy (Disabled/Optional/Mandatory), transport reconnection per protocol, ReconnectPolicy. N0044 specifies shutdown command routing: GetAccountInfo permitted (read-only), ConfConnect/Disconnect rejected.

### Goal
Implement the M20 policy layer for codec auto-mode (N0041), SRTP + transport reconnection (N0042), and shutdown command routing (N0044) as specified by the RFC graph §29-32. Each policy must be self-contained within its target file and fully testable.

### Purpose
Provide the runtime policy configuration that governs how siprs handles codec selection (auto vs explicit), media security (SRTP on/off/optional), transport resilience (reconnection per protocol), and safe shutdown behavior (read-only commands permitted, mutating commands rejected). These policies complete the M20 extension to the config and error subsystems.

### Motivation
M20 RFC sections §29-32 define the policy layer that bridges static configuration (P0-1/P0-2) and dynamic runtime behavior (P0-7/P0-8). Without these policies, the reactor would lack the decision logic for codec priority ordering, SRTP enforcement, transport failover strategy, and graceful command rejection during shutdown.

### Constraints
- FFI crate (P0-9) is not yet available: codec priority setting via pjsua_codec_set_priority must use a mockable/injectable wrapper.
- ConfConnect/ConfDisconnect RuntimeCommand variants are added by P0-8 (AudioWorkerTask) — P1-1 shutdown routing depends on those variants existing.
- TransportConfig types (UdpTransportConfig, TcpTransportConfig, TlsTransportConfig) are defined in N0015 (P0-1). ReconnectPolicy must be compatible with those types.
- SRTP feature flag (cfg(feature = "srtp")) must be declared in Cargo.toml before implementation.

## Acceptance Criteria

- [Happy path] Codec auto mode: configure_codecs() with empty preferred_codecs sets Opus=255, PCMU=254, and all other codecs=0. All 15 unit tests pass. SrtpPolicy enum constructs all 3 variants. dispatch_command permits GetAccountInfo during shutdown.
- [Error case] Codec FFI failure: configure_codecs() propagates error via SipError. SRTP config invalid: Mandatory policy with srtp feature disabled returns InvalidConfig. Shutdown dispatch: ConfConnect returns InvalidState error.
- [Edge case] Codec priority boundary: Opus=255 (u8::MAX), PCMU=254, disabled=0. All non-PCMU/non-Opus codecs get priority 0. Unknown codec IDs (empty string, long prefix, unicode) all get 0. Shutdown catch-all: RuntimeCommand variants not explicitly matched are all rejected.

## Invariants

- [Normal condition] Codec auto mode: Opus=255, PCMU=254, all others=0. SRTP: Disabled/Optional/Mandatory enum is feature-gated. Shutdown: GetAccountInfo passes through, media commands rejected.
- [Error invariant] On codec set_priority failure: original codec priorities are preserved (no partial update). On invalid SRTP config: client initializes with SRTP disabled as fallback. On shutdown dispatch error: error is returned to caller, reactor state remains consistent.
- [Internal state invariant] ReconnectPolicy: per-protocol fields are never in an inconsistent state (e.g., TCP with TLS-only config). dispatch_command: is_shutting_down flag is only modified by shutdown() entry point, not by dispatch itself.
- [Boundary invariant] Codec priority values: Opus=255 (u8::MAX), PCMU=254 (u8::MAX-1), disabled=0 (u8::MIN). ReconnectPolicy retry counts must be >= 0. Shutdown rejection messages are consistent across all rejected commands.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C042 — N0041→N0040

- **Precondition**: CallMediaPreferences::preferred_codecs may be empty (auto mode) or contain 1+ Codec entries (explicit mode). The SIP client must be initialized and codecs enumerable via enumerate_codecs().
- **Postcondition**: When preferred_codecs is empty: configure_codecs() sets Opus/48000/2ch priority=255, PCMU/8000/1 priority=254, all others priority=0. When preferred_codecs is non-empty: auto mode is bypassed, user-specified codecs are used in SDP offer/answer without priority modification.
- **Invariant**: Opus always gets the highest priority (255) in auto mode. PCMU always gets the second-highest (254). All other codecs get 0 (disabled). Priority values are in u8 range [0, 255]. Non-PCMU/non-Opus codec IDs are never assigned a value > 0.

### C043 — N0042→N0015

- **Precondition**: TransportConfig enum (UDP/TCP/TLS) and TlsConfig struct are defined in src/config/transport_ice_spec.rs (N0015). Feature flags tls and srtp are declared in Cargo.toml.
- **Postcondition**: SrtpPolicy enum (Disabled/Optional/Mandatory) is defined and feature-gated with #[cfg(feature = "srtp")]. ReconnectPolicy struct defines per-protocol reconnection strategy (UDP, TCP, TLS). Transport validation rejects Mandatory+Optional when srtp feature is disabled.
- **Invariant**: SRTP feature gate is active: when cfg(feature = "srtp") is false, SrtpPolicy::Mandatory and SrtpPolicy::Optional are either compile-time unavailable or rejected at config validation. SrtpPolicy::Disabled is always available regardless of feature flag.

### C045 — N0044→N0043

- **Precondition**: Shutdown sequence is defined (N0043, src/state/shutdown_specification.rs). is_shutting_down flag is accessible by the dispatch function. RuntimeCommand enum includes GetAccountInfo (from N0010, P0-6) and will include ConfConnect/ConfDisconnect (from P0-8 AudioWorkerTask).
- **Postcondition**: When is_shutting_down=true: GetAccountInfo variants pass through to execute_get_account_info() (read-only permitted). ConfConnect and ConfDisconnect variants return Err(SipError::invalid_state("shutting down")). All other RuntimeCommand variants return Err(SipError::invalid_state("shutting down")) via catch-all. When is_shutting_down=false: normal dispatch proceeds unchanged.
- **Invariant**: GetAccountInfo is always permitted during shutdown (read-only invariant). ConfConnect and ConfDisconnect are always rejected during shutdown. No RuntimeCommand variant causes a panic during shutdown dispatch. The dispatch decision is deterministic based solely on is_shutting_down and the command variant.

## Boy Scout Rule

- [Boy Scout — Translatability Plan]

  ## 1. extract_codec_priority() from inline match
  RFC §29 contains an inline match block for codec priority assignment. Extract into a named function
  `fn codec_priority_for_id(codec_id: &str) -> Option<u8>` that returns Some(255)/Some(254)/Some(0)/None
  for unknown. This makes the dispatch logic translatable:
    "determine priority for this codec ID → if known, call set_priority → if set fails, return error"

  ## 2. dispatch_command as a pure function
  The shutdown routing match block should be extracted as a pure function:
  `fn should_allow_during_shutdown(cmd: &RuntimeCommand) -> Result<(), SipError>`
  This separates the decision logic from the reactor loop, making it testable and translatable:
    "if shutting down, match command → GetAccountInfo OK, ConfConnect/ConfDisconnect rejected, all else rejected"

  ## 3. Named constants for priority values
  Replace magic numbers 255, 254, 0 with:
    pub(crate) const CODEC_PRIORITY_OPUS: u8 = 255;
    pub(crate) const CODEC_PRIORITY_PCMU: u8 = 254;
    pub(crate) const CODEC_PRIORITY_DISABLED: u8 = 0;

  ## 4. ReconnectPolicy as a struct with named fields, not a tuple
  ReconnectPolicy should be a struct with named fields (udp_retry: RetryConfig, tcp_retry: RetryConfig, tls_retry: RetryConfig) so that
  construction reads as "ReconnectPolicy { udp_retry: RetryConfig::default(), tcp_retry: ..., tls_retry: ... }"
  rather than a positional tuple.

  ## 5. Clean up stub artifacts
  Replace pub struct Config {} and pub enum Error {} stubs in all three target files with real implementations.
  Add #[::STUB::] markers only for parts that genuinely depend on future tickets (FFI calls, runtime integration).

  ## 6. Code outside scope
  N0040 (codec_policy_fallback.rs) and N0015 (transport_ice_spec.rs) and N0043 (shutdown_specification.rs) 
  remain stubs — they are not touched by P1-1. This is acceptable as they belong to separate tickets.
