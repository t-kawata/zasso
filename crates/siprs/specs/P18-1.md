# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

# Target ticket is P18-1: Consumer/bindgen alignment — pjsua-native build repair (§62.31–62.35)

**Ticket Key**: P18-1 · **Phase**: 18

**RFC Source**: `RFC-ROOT.md`

## Background

### Goal
Make `cargo build --features pjsua-native` compile with **0 errors**, restoring the real PJSIP FFI layer to a buildable state, and make `make test-integration` (Docker Asterisk/coturn + `tests/sip_integration.rs`) run green in CI. This is the consumer half of the producer/consumer split (design brief §5): Ticket A repairs siprs' own consumption of PJSIP; P18-2 (producer) generates the prebuilt artifacts.

### Purpose
Without `pjsua-native`, siprs compiles only against deterministic stub bindings (`src/ffi/bindings.rs` stub_aliases), so the crate's real SIP backend — registration, calls, DTMF, media — is unverifiable at the heart. `cargo check --features pjsua-native` currently fails with **69 errors** across ~15 categories (reproduced locally on this branch). This ticket closes the gap by (1) emitting the enum/const symbols the code references via bindgen, (2) adapting code to PJSIP 2.17.0's actual symbols/fields, and (3) fixing pure-Rust errors (imports, FFI signatures).

### Motivation
RFC §62.31 / design brief §3.2 identify the build failure as the top blocker: the real-PJSIP integration suite (docker Asterisk/coturn) is unrunnable until the crate compiles. Round 3 (P17-8/9/10) settled the surrounding design; round 4 must make the FFI layer buildable. A naive allowlist expansion is insufficient (design brief §3.3) — the errors include enum enumerators that type-allowlist cannot emit (PJ_SUCCESS is `enum` in pj/types.h:93), symbols absent from the vendored tree (`PJSUA_CALL_NULL`, `PJ_CRED_DATA_PLAIN_PASSWD`), and struct fields that do not exist in 2.17.0 (`pjsua_codec_info.encoding_name/clock_rate`).

### Constraints
- Vendored PJSIP stays at **2.17.0** — no upgrade (2.17 is the latest release; C139 invariant).
- `BINDGEN_ALLOWLIST_TYPES`/`FUNCTIONS`/`VARS` + new `BINDGEN_ENUM_TYPES` remain the **single** bindgen entry point (C140 invariant).
- Link set is derived from the resolved `lib/` directory — never a hardcoded module list (C141 invariant).
- 4-stage resolution (prebuilt → system → vendored-source CMake → fail-stop) is **fail-stop**; warning-and-continue is prohibited (C142 invariant).
- `PJSUA_CALL_NULL` / `PJ_CRED_DATA_PLAIN_PASSWD` must not depend on bindgen output — move to a crate-internal constant module / the real `PJSIP_CRED_DATA_PLAIN_PASSWD` symbol (N0101).
- Round-3 settled decisions (§62.21–62.30) are not rewritten (C137 invariant); prebuilt-first search order preserved (C138 invariant).
- The default build (no `pjsua-native`) must keep compiling against stub bindings.

## Acceptance Criteria

- **[Happy path]** `cargo build --features pjsua-native` completes with **0 errors** on a host with the prebuilt present (aarch64-apple-darwin): bindgen generates `pjsip_inv_state` as a Rust enum (`NULL..DISCONNECTED`) plus `PJ_SUCCESS`/`PJ_ENOMEM`/`PJ_EBUSY`/`PJ_EINVALIDOP`, link directives (link-search + `static=pjproject`) are emitted, and `make test-integration` (Docker Asterisk/coturn + `tests/sip_integration.rs`) runs green in CI.
- **[Error case]** With no prebuilt, no system PJSIP, and cmake unavailable, `cargo build --features pjsua-native` fails loudly with a **fail-stop panic** naming the missing PJSIP install and the RFC §28.4 package list — never a `cargo:warning`-and-continue that yields a partially-linked binary; `SIPRS_STAGE_PREBUILT=1` staging on a failed build writes nothing to `vendor/prebuilt/<target>/`.
- **[Edge case]** Both feature modes compile: default (stub) build stays green and native (`pjsua-native`) build reaches 0 errors; `codec_id_to_name_rate` handles `""`/no-slash/non-numeric/overflow by returning `(raw, 0)`; `SIPRS_STAGE_PREBUILT` toggles staging on/off; a lib/ directory containing only `pjproject.lib` (Windows) resolves to the single `static=pjproject` emit; round-3 settled files (§62.21–62.30) remain untouched (C137).

## Invariants

- [Normal condition] The bindgen allowlist set (`BINDGEN_ALLOWLIST_TYPES`/`FUNCTIONS`/`VARS` + `BINDGEN_ENUM_TYPES`) must be consistent with every symbol the `pjsua-native` code references: each referenced constant, enum variant, struct field, and function signature is either emitted by bindgen or defined in the crate — nothing references a missing symbol (the 69-error state is the violation being fixed).
- [Error invariant] On resolution failure (prebuilt absent + system absent + cmake unavailable), the build fails loudly with a fail-stop panic — never a `cargo:warning`-and-continue that yields a partially-linked binary; `SIPRS_STAGE_PREBUILT=1` staging must not write to `vendor/prebuilt/<target>/` unless the build succeeded.
- [Internal state invariant] The stub-mode bindings (`src/ffi/bindings.rs` stub_aliases) and the native bindgen bindings expose the same surface so shared code (`m20_callstate_mapping.rs`, `observability_metrics.rs`, `error_design_siperror.rs`) compiles under both feature modes; `pjsip_inv_state`/`pjsua_call_media_status` resolve identically (`::VARIANT`) in both modes.
