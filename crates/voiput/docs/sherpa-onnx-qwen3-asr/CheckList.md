## プロジェクト固有の補足制約

### アーキテクチャ制約

- [ ] trate crate のトレイト設計は2層構造（`AsrBackendCore` + `AsrBackendExt`）を守ること。コア機能と拡張機能を分離する
- [ ] `SttEngine::Local { backend: LocalAsrKind }` のバリアント定義は全列挙型の網羅性を保つこと
- [ ] 音声認識エンドポイントへのリクエスト送信部分**のみ**を抽象化する。VAD・PostCorrection・ストリーム制御は共通パイプラインとして維持する
- [ ] 音声認識エンジンによってパイプラインが分岐してはならない。リクエスト先の違いを抽象化の唯一の責務とする
- [ ] `LocalRecognizer` は内部に `Box<dyn LocalAsrBackend>` を持ち、将来のモデル追加（Whisper, SenseVoice 等）に備えた拡張可能な設計とすること
- [ ] `Qwen3AsrBackend` の `OfflineRecognizer` は `Mutex` で保護すること（選択肢C）

### モデル管理パターン（VAD一貫性）

- [ ] モデルファイルは `models/qwen3-asr/` サブディレクトリに配置（`tokens.txt` 重複回避のため）
- [ ] `constants.rs` にモデルファイル名定数を定義する（VADモデルと同じパターン）
- [ ] `types.rs` に `Qwen3AsrModelPaths` 構造体を定義する（VADの `VadModelPaths` と同パターン）
- [ ] 推論パラメータ（`num_threads`, `provider` 等）は `Qwen3AsrConfig` としてモデルパスと分離する
- [ ] モデルダウンロードは `build.rs` で行い、既存のVADモデルダウンロード機構（`curl` / `PowerShell`）を再利用する
- [ ] `models/` ディレクトリにモデルファイルが存在する場合、`build.rs` は再ダウンロードしない（既存の `cargo:rerun-if-changed=models/` パターンを踏襲）
- [ ] モデルファイルのロードエラーは `OfflineRecognizer::create()` のエラーを `anyhow::Result` で伝播する（選択肢A）
- [ ] `VoiputConfigBuilder.validate()` で `SttEngine::Local` 時のモデルパス必須チェックを追加する
- [ ] `model_dir` と `resolve_vad_model_path()` のパス解決ロジックを流用する
