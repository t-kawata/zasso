# Release v0.24.337

## Summary
ggufrs M4 milestone completes the HTTP server mode with Axum-based router, OpenAI/Anthropic-compatible handlers, server lifecycle management, and integration tests — enabling ggufts to run as both a library API and an embedded HTTP server within the same process.

## What's Changed
- **feat: Axum router + handler implementation (M4-1)**
  - Added `server/router.rs` with `AppState`/`AppError` type aliases and `build_router()` function
  - Added `server/openai.rs` with 3 endpoints: OpenAI `/v1/chat/completions`, model list `/v1/models`, Anthropic `/anthropic/v1/messages`
  - Anthropic endpoint uses `llm-bridge-core` for request/response protocol transform
  - 20 unit tests covering all handler paths, error variants, and routing

- **feat: Server lifecycle management (M4-2)**
  - Added `GgufEngine::start_server()` — `build_router()` → `TcpListener::bind` → `axum::serve` with graceful shutdown
  - Added `GgufEngine::new_with_auto_start()` — conditional auto-start via `ServerConfig.auto_start_server`
  - Added `Drop` implementation — `AbortHandle`-based resource cleanup
  - Added `shutdown_signal()` — Ctrl+C and SIGTERM with graceful shutdown
  - RFC `expect()` calls replaced with `tracing::warn` (Boy Scout improvement)

- **test: Server integration tests (M4-3)**
  - Added `tests/server_integration_test.rs` — lifecycle, model list, error response scenarios via HTTP
  - Verified all 5 end-to-end scenarios: lifecycle, models, chat completions, Anthropic endpoint
  - 159 total tests passing (158 unit + 1 integration)

- **chore: Cleaned up stale STUB markers in Cargo.toml**
