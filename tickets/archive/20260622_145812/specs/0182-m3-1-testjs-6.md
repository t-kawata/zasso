# M3-1: test.js — 6段階検証スクリプト

## Summary

`run.sh` が起動した状態で実行する 6 段階のテストパイプライン。各段階の結果を個別に表示し、障害箇所を特定可能にする。Node.js ビルトイン `http` モジュールのみで実装し、外部 npm 依存を一切持たない（Q16）。`--fail-fast` フラグで初回失敗時に停止可能。

**本チケットの意義**: M0-1〜M2-1 までの全ユニットテストはモック不使用で完了したが、実機での総合動作確認（setup.sh の環境構築→run.sh の起動→API 応答）は未検証である。test.js はこの検証を自動化し、障害箇所を Stage 単位で特定する。

## Background

これまでのチケットで実装されたスクリプト群は、各々がユニットテストでカバーされている。しかし、**実際の MTPLX サーバー + Proxy が正しく連携するか**の確認は、実機で実行する結合テストに委ねられている。

test.js は以下の 3 層の動作を一貫して検証する：

| レイヤー | 検証対象 | Stage |
|---------|---------|-------|
| プロセス生存 | MTPLX / Proxy が起動しているか | 1, 4 |
| MTPLX API | OpenAI 互換 API が正しく応答するか | 2, 3 |
| Proxy API | Anthropic 互換変換が正しく動作するか | 5, 6 |

**決定事項の実装:**
- Q6: 6段階テスト＋モデル名検証＋`--fail-fast`
- Q9: 6段階＋モデル名内容検証
- Q10: test.js のみ Node.js（他スクリプトは Shell）
- Q16: Node.js ビルトイン `http` モジュールのみ（外部依存ゼロ）

### 実装上の注意点

1. **外部依存ゼロの徹底**: `require('http')` と `require('child_process')` のみ。npm install 不要。
2. **`--fail-fast` の実装**: `process.argv.includes('--fail-fast')` で判定。各 Stage の失敗後に `if (FAIL_FAST) { summarize(); return; }`。
3. **エラーハンドリング**: HTTP リクエストは try/catch + `httpRequest` の reject を両方カバー。プロセス確認は `execSync` の例外を catch → `false`。
4. **タイムアウト**: `http.request` の `timeout` オプション + `req.on('timeout')` → `req.destroy()` + `reject`。
5. **テスト容易性**: `httpRequest` は Promise ベースのため、テストでモックサーバーを立てて結合テスト可能。ただし本チケットではモックサーバーは使用しない（代わりに制御フローのテストにフォーカスする）。

## Test Plan

### ユニットテスト計画

テストファイル: `tests/test-test.js`（Node.js、`require('assert')` のみ、外部テストフレームワーク不使用）

**基本方針: モック（外部コマンドの代替バイナリや関数の置き換え）は原則禁止。**

test.js は以下のレイヤーに分割してテストする：

| レイヤー | テスト方法 | モックの有無 |
|---------|-----------|-------------|
| **printStage** / **summarize** | 純関数。`console.log` の出力をキャプチャして検証 | なし |
| **httpRequest** | 実際に `http.createServer` でテスト用サーバーを起動して結合テスト | なし（実サーバー） |
| **findMTPLXProcess** / **findProxyProcess** | `pgrep` の挙動に依存。既知のプロセス名（`node`, `bash` 等）でテスト。不在時は存在しないプロセス名でテスト | なし（実 pgrep） |
| **main 制御フロー** | test.js 全体を `node test.js` で実行。サーバー不在時のエラーハンドリングを検証（各 Stage の try/catch が正しく動作するか） | なし |
| **`--fail-fast` フラグ** | `node test.js --fail-fast` で実行。サーバー不在時、最初の失敗で停止するか確認 | なし |

**テストケース一覧（test.js のユニットテスト）:**

## Boy Scout Rule — 翻訳可能性計画

本チケットで新規作成する `test.js` において、以下の翻訳可能性基準を満たす：

1. **関数名は動詞句**: `httpRequest`（HTTPリクエスト）/ `findMTPLXProcess`（MTPLXプロセス検索）/ `findProxyProcess`（Proxyプロセス検索）/ `printStage`（段階出力）/ `summarize`（集計）
2. **変数名はドメイン概念**: `MTPLX_PORT`, `PROXY_PORT`, `MODEL_NAME`, `TIMEOUT`, `passed`, `failed`, `FAIL_FAST`
3. **一関数一責務**:
   - `httpRequest`: HTTP 通信のみ（JSON パースも内部で完結）
   - `findMTPLXProcess` / `findProxyProcess`: プロセス生存確認のみ
   - `printStage`: 出力フォーマットのみ
   - `summarize`: 集計 + exit のみ
4. **ハードコード値排除**: ポート番号・モデル名・タイムアウト値は全て環境変数経由。デフォルト値はコメント付きで const 宣言
5. **エラーは throw せず Promise reject**: `httpRequest` はエラーを reject で伝播。上位の try/catch で一括処理
6. **外部依存ゼロ**: Q16 厳守。`require('http')` と `require('child_process')` のみ
