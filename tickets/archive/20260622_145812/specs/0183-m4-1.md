# M4-1: 全スクリプト連携テストと障害モード検証

## Summary

mycc プロジェクトの最終フェーズ。M0-1〜M3-1 で実装された全スクリプト（common.sh / doctor.sh / setup.sh / run.sh / test.js）が連携して期待通り動作することを検証する。10 種の障害モード全てを再現し、各スクリプトが適切なエラー表示と対策を示すことを確認する。また、ドキュメント（Appendix A〜D）の完全性を検証する。

**本チケットはコードの新規作成ではなく、統合テストスクリプトの作成と全スクリプトの最終検証を目的とする。**

## Background

これまでの 6 チケットで mycc プロジェクトの全スクリプトが実装され、各々がモック不使用のユニットテストで検証されている。しかし、以下は未検証である：

1. **スクリプト間の連携**: doctor.sh → setup.sh → run.sh → test.js の実行順序が正しく動作するか
2. **実機での成功パス**: MTPLX + Proxy が実際に起動し、API 応答を返すか
3. **障害モード 10 種**: 各障害に対してスクリプトが適切なエラー表示と対策を示すか
4. **ドキュメントの完全性**: Appendix の手順が実際に動作するか

本チケットはこれらの最終検証を実施する。

**参照設計書:**
- RFC.md §7. エラーハンドリングと障害モード（10 種の障害モード一覧）
- RFC.md Appendix A-D（使用手順、ショートカット、トラブルシューティング、モデル切替）
- Tickets.md §M4-1（詳細仕様）

### 実装上の注意点

1. **MTPLX 環境依存のテスト**: 正常系 E2E（setup.sh → run.sh → test.js）は実際の MTPLX + 27B モデルが必要。このテストは CI では実行不可。実行時は明示的にスキップする。
2. **障害モード #1（非 Apple Silicon）**: 実機以外では再現不可能。`uname`/`sysctl` の PATH 操作で代用可能だが、本チケットでは test-e2e.sh 内で `UNAME_OUT=x86_64` を使用した簡易テストを提供する。
3. **test-e2e.sh の設計**: MTPLX 環境の有無を自動検出し、実行可能なテストのみを実行する。
4. **不具合修正の範囲**: 検証で発見された不具合は本チケット内で修正する。ただし大規模なリファクタリングが必要な場合は別チケットとする。

## Test Plan

### 統合テスト計画

テストファイル: `tests/test-e2e.sh`

test-e2e.sh は以下の構造を持つ：

```bash
#!/bin/sh
# test-e2e.sh — 統合テスト（全スクリプト連携 + 障害モード検証）
#
# 使用方法:
#   sh tests/test-e2e.sh              # 全テスト実行
#   sh tests/test-e2e.sh --skip-heavy  # MTPLX 不要のテストのみ
```

**テストケース一覧:**

| # | カテゴリ | ケース名 | テスト方法 | 環境依存 |
|---|---------|---------|-----------|---------|
| 1 | 連携 | doctor.sh → setup.sh → run.sh → test.js | フルパイプライン実行 | MTPLX 必須 |
| 2 | 冪等性 | setup.sh 2回実行 | 2回連続実行 → リソース一致 | なし |
| 3 | 障害#4 | ポート占有 → run.sh エラー | `nc -l` で port を予約 → run.sh がエラー終了 | なし |
| 4 | 障害#5 | モデル不在 → run.sh エラー | models/ を退避 → run.sh がエラー終了 | なし |
| 5 | 障害#7 | MTPLX 未起動 → test.js Stage 1 失敗 | test.js 単体実行 → Stage 1 ❌ | なし |
| 6 | 障害#9 | サーバーコマンド検出失敗 → run.sh エラー | mtplx/lightning-mlx 不在 → detect_serve_cmd エラー | なし |
| 7 | フラグ | test.js --fail-fast | `--fail-fast` で Stage 1 のみ実行 | なし |
| 8 | 設定 | MODEL_VARIANT=speed | Speed 版モデル指定 | MTPLX 必須 |

**skip-heavy フラグ**: MTPLX 環境が必要なテスト（#1, #8）をスキップして実行可能。

### ユニットテスト不可能な項目（例外）

真にテスト不可能な項目のみを列挙する：

| 項目 | 理由 |
|------|------|
| 障害#1（非 Apple Silicon） | 検証には Intel Mac または VM 環境が必要。テスト環境で Apple Silicon 以外を再現不可 |
| 障害#6（MTPLX readiness タイムアウト） | 実際の MTPLX 起動後のタイムアウトには 120 秒 + モデルロード時間が必要。run.sh のユニットテストで curl タイムアウトは検証済み |
| 障害#8（Proxy 変換不良） | Proxy の内部動作の不具合を再現するには実際の proxy 設定変更が必要。test.js のユニットテストで段階的検証は完了 |
| 障害#10（速度不足） | 観測のみの項目であり、検証対象外 |

### 手動テスト計画

以下の項目は自動テストが不可能なため、手動で検証する：

1. **E2E 正常系**: `./setup.sh` → `./run.sh`（別ターミナル）→ `node test.js` を手動実行
2. **Ctrl+C シャットダウン**: run.sh 起動中に Ctrl+C → 両プロセス停止を確認
3. **ドキュメント検証**: Appendix A〜D の手順が実際に動作するか確認

## Boy Scout Rule — 翻訳可能性計画

本チケットで新規作成する `tests/test-e2e.sh` において、以下の翻訳可能性基準を満たす：

1. **関数名は動詞句**: `run_e2e`, `test_port_busy`, `test_model_missing`, `check_env`
