# M6-3: 設定検証補完（m#7/m#11）

## Summary

`AppConfig::validate()` において未実装の 3 項目（url_prefix 正規化、alias key 衝突チェックのロジック誤り修正、alias 競合ログ）を実装する。あわせて alias key 同士の重複チェックを追加する。

## Background

REMAININGS.md で発見された m#7（AppConfig::validate() 複数検証項目未実装）および m#11（alias 検証ロジックが RFC 不変条件と異なる）の 2 件を一括解決する。

現在の `validate()` は以下の問題を抱えている：

1. **url_prefix 正規化が未実装** (m#7 #1): RFC §2.1 #7 で要求されている先頭 `/` 付与・末尾 `/` 除去の正規化処理が存在しない。現在は `build_router()` 側で空 prefix の nest 回避をしているが、正規化自体は行われていない。

2. **alias 衝突チェックのロジック誤り** (m#7 #3, m#11): 現在は alias の **値（value）** と public model 名を比較しているが、RFC が意図するチェックは alias の **キー（key）** が public model 名または他の alias key と重複しないことである。

3. **global alias と provider alias の競合ログ欠落** (m#7 #2): 競合自体は許容（provider alias 優先）する設計だが、競合発生時に `tracing::info!` によるログ出力も行われていない。

## Scope

`src/config/validate.rs` に以下の修正を加える：

1. **`fn normalize_url_prefix(prefix: &str) -> String`** の追加
   - 空文字列 → 空文字列
   - 先頭に `/` がない → 先頭に `/` を付与
   - 末尾に `/` がある → 末尾の `/` を除去
   - `/` のみ → 空文字列
   - `//` → 空文字列

2. **`AppConfig::validate()` 内での url_prefix 正規化呼び出し**
   ```rust
   self.global.url_prefix = normalize_url_prefix(&self.global.url_prefix);
   ```
   検証ブロック冒頭で実行する。

3. **alias key 衝突チェックの修正**
   - 現在: alias の value と public model 名を比較
   - 修正後: alias の key が public model 名と衝突するかチェック

4. **alias key 同士の重複チェック追加**
   - 同一 provider 内で alias key が model.public と重複していないかチェック
   - （BTreeMap のキー重複は serde が防ぐが、model 定義との関係を明示的に検証）

5. **`fn log_alias_conflicts()` の追加**
   - global alias と provider alias の競合を `tracing::info!` でログ出力
   - 競合時は provider alias が優先されることをログに明記

## Non-scope

- ポート番号や timeout 値の検証ロジック変更（現状維持）
- `ConfigError` 型の variant 追加（現状の `DuplicateAlias` で対応可能）
- 既存の正常設定テストの改変
- `build_router()` 側の url_prefix 処理変更（正常系は現状維持、正規化済みの値が渡されることを前提とする）

## Boy Scout Rule — 翻訳可能性計画

1. **`normalize_url_prefix()` 関数**: 関数名は動詞句で処理内容を明確に表現。コメントには RFC 準拠の入出力対応表を記載し、テストケースと整合させる
2. **alias 衝突チェックのロジック**: key と public 名の比較に修正し、`alias_key` と `public_names` という変数名で「何と何を比較しているか」が一目でわかるようにする
3. **`log_alias_conflicts()` 関数**: 関数名と引数名で「どの alias が」「どの provider で」競合しているかが明確に伝わるようにする
4. **エラー文言の一貫性**: `ConfigError::DuplicateAlias` の `Display` 実装は現状維持。「alias X conflicts with existing model Y」の形式を崩さない
5. **スコープ外だが発見次第報告**: 既存コードの `ValidationFailed(DuplicateModel(...))` の誤用（L59-78）は発見したが、本チケットでは修正しない（既存動作維持）
