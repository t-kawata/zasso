# Layer 4 相互接続試験 + 新機能テスト層マッピング（P0）

### 実装判断

1. **call_reject の実装方法**: DualClientContext の `answer_b(call_id, 486)` で client_b が 486 Busy Here を返し、`wait_for_event_a(…CallRejected…?)` で確認する。注意: 現状の API では `SipEventPayload::CallRejected` が存在するか確認が必要。存在しない場合は `CallDisconnected` と `HangupSource` の組み合わせで判断

2. **early_media_received の代替**: SIPp 依存を避けるため、Asterisk の `extensions.conf` に 183 Session Progress を送出するテスト用エクステンションを追加することを検討。ただし Asterisk の仕様上、183 は media 提供時にしか送出されないため、Asterisk Echo の挙動変更が必要になる可能性あり。優先度を下げてスキップ継続も許容

3. **FreeSWITCH テスト環境**: `tests/docker/freeswitch/` ディレクトリを作成し、FreeSWITCH の Docker Compose 設定を追加する。ただし FreeSWITCH の Docker イメージサイズが大きく、CI ではスキップする可能性が高いため `#[ignore]` を付与

## Boy Scout Rule — 翻訳可能性計画

1. **`call_reject` の実装**: DualClientContext の `answer_b(486)` と `wait_for_event_a(…CallRejected…?)` の組み合わせは「client_b が 486 で応答 → client_a が CallRejected を受信」と翻訳可能。ヘルパー関数に適切な名前を付与する
2. **`tests/interop/asterisk.rs`**: 各テスト関数は「asterisk_register_auth_success」「asterisk_invite_bye_normal」のように「{ターゲット}_{シナリオ}_{期待結果}」の命名規則で統一。関数呼び出しの並びがそのままテスト手順の日本語訳になるように構成する
3. **`tests/interop/freeswitch.rs`**: 同上の命名規則
4. **ハードコード定数の抽出**: テスト内に現れる SIP ポート番号（5060）、タイムアウト値、ユーザー名/パスワードは、`tests/common/mod.rs` の定数（`ASTERISK_SIP_PORT` 等）を参照し、テストコード内でのマジックナンバー直書きを排除する
5. **エラー握りつぶしの防止**: 既存テストの `eprintln!` スキップを正当な理由とともに `SipError::skipped()` または `ignore` パターンに置き換え、`Ok(())` だけ返して正常終了と見せかけないようにする
