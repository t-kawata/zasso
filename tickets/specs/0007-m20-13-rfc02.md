# M20-13: 受け入れ基準検証・リリース判定（RFC02 対応版）

## Summary

RFC01 §50（全13項目）および RFC02 追加項目（全5項目）の計18の受け入れ基準を検証し、siprs crate のリリース可否を判定する。全テスト（Layer 1〜4、相互接続試験含む）の通過、3 OS でのビルド成功、全 feature flag 組み合わせのコンパイルチェックに加え、RFC02 付録B の既存修正箇所が正しく反映されていることを確認する。

## Background

siprs crate は M20 フェーズで RFC02 に基づく拡張実装（P0〜P3）を完了した。これに伴い、RFC01 §50 の受け入れ基準13項目に加え、RFC02 の全設計判断（付録A 18決定）の充足を確認する必要がある。特に以下の観点が重要：

1. **RFC02 実装の完全性**: 全 M20 サブチケット（M20-1〜M20-12）が「reviewed」ステータスであり、その完了確認が必要
2. **回帰テスト**: RFC02 実装が既存機能を破壊していないことの確認
3. **相互接続性**: 実 PBX（Asterisk / FreeSWITCH）との相互接続試験の完了確認
4. **CI/CD パイプライン**: Docker Integration Job および Prebuilt Refresh Pipeline の動作確認
5. **RFC02 付録B 反映確認**: RFC01 §29 `configure_codecs` コードブロックの修正（Opus=255, PCMU=254）がソースコードに反映されていること

## Scope

以下の18項目の受け入れ基準を検証し、PASS/FAIL マトリクスを作成する：

### RFC01 §50 基準（13項目）
1. **3 OS ビルド成功**: macOS arm64, Ubuntu x86_64, Windows x86_64 での cargo build 成功確認
2. **PJSUA バインディング自動生成**: bindgen による FFI バインディングが再現性を持って生成されることの確認
3. **prebuilt 優先・source build fallback**: build.rs の二段階戦略が正しく機能することの確認
4. **複数 account 独立 register/unregister**: 複数アカウントの同時登録・個別解除が正しく動作することの確認
5. **未登録アカウントで発信可能**: `allow_outbound_without_register = true` の動作確認
6. **UDP/TCP/TLS, SRTP, ICE/STUN/TURN**: 全トランスポートモードの設定通り動作確認
7. **PCMU/Opus のみ交渉**: 他 codec 無効化、RFC02 §6.4 auto モード反映確認
8. **DTMF 3方式の送受信イベント**: Inband / SIP INFO / RFC4733、DtmfSent 二段構え含む
9. **全列挙イベント発火**: `SipEventPayload` 全バリアント + RFC02 追加イベントの到達性確認
10. **AudioChunkPair format guarantee**: format 保証付きの音声チャンク取得確認
11. **複数 audio source 同時注入・切替**: 通話中の音声ソース動的切替確認
12. **全 API `Result<T, SipError>` 統一**: コンパイル時検証
13. **SipClient: Send + Sync**: コンパイル時検証

### RFC02 追加項目（5項目）
14. **blocking_read ゼロ**: コードベースに `blocking_read()` / `blocking_write()` が存在しないこと
15. **Dual Client 動作確認**: 2 Client 同時使用でイベント分離が正しいこと
16. **Shutdown 中 GetAccountInfo 許可**: Shutdown 状態でも registration 最終確認が可能であること
17. **Docker Integration Job 動作**: CI 上で全統合テストが PASS すること
18. **付録B 修正箇所反映確認**: `configure_codecs` コードブロックが Opus=255, PCMU=254 に修正されていること

## Boy Scout Rule — 翻訳可能性計画

本チケットは新規コードを書かず検証のみを行うため、大規模な翻訳可能性改善は対象外。ただし、検証過程で発見された以下の点を改善する：

1. **grep 結果の `tests/common/mod.rs:37` コメント**: `blocking_read 回避` とあるが、このコメント自体が「回避」というネガティブな表現を含む。RwLock の操作として自然な表現（`read().await により非ブロッキング読み取り`）に修正する。
2. **既存 `[::STUB::]` マーカーの状況確認**: 3件のスタブのうち、本検証で関連する `runtime/reactor.rs:943`（IncomingCall ハンドリング）については M20-4 の既知範囲外として spec で明記。スタブ自体は残置し、犯罪記録の更新は不要。
3. **検証スクリプトの翻訳可能性**: 受け入れ基準検証スクリプトを作成する場合、関数名は `verify_<item>`, 変数名はドメイン概念を表現すること。ハードコード値（PASS/FAIL 閾値等）は名前付き定数に抽出する。
