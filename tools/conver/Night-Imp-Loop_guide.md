# Night-Imp-Loop 説明書

Night-Imp-Loop（ナイトインプループ）は、**昼は人間が仕様と設計をまとめ、夜はAIがその通りにコードを書く**ための仕事の進め方です。[file:63][file:62]

この方法では、仕事を「外側ループ」と「内側ループ」の二層に分けます。外側ループは人間が進める設計のループ、内側ループは `conver.js` が自動で回す実装のループです。[file:62]

## 全体像

- **昼（人間）**: 何を作るかを決め、仕様書や設計書をまとめる。[file:63]
- **夜（AI）**: 決まった仕様をもとに、チケット単位で実装・修正・確認を進める。[file:63][file:62]

人間は「何を作るか」「どうあるべきか」に集中し、AIは「どう書くか」という作業を担当します。[file:63]

## 外側ループ

外側ループは、**昼に人間が進める設計のループ**です。[file:62]
コードを書く前に、チームで話し合い、仕様を決め、AIに任せる仕事を整理します。[file:63]

主な流れは次の通りです。

1. **`/grill-me-for-rfc`**  
   チームで対話しながら、最初の設計書（RFC）を作ります。AIが質問し、人間が答えながら内容を固めます。[file:62]

2. **`/formulate-tickets`**  
   設計書を、AIが実行しやすい小さな作業単位（チケット）に分解します。夜のAIの仕事リストを作る段階です。[file:62]

3. **`/grill-me-for-next-rfc-ja`**  
   夜の実装で見つかった不足やズレをもとに、次の世代の設計書を作ります。[file:62]

4. **`/formulate-tickets-for-next`**  
   新しい設計書をもとに、追加で必要なチケットを足します。次の夜のAIの仕事を準備します。[file:62]

5. **`/merge-omissions-into-root-rfc`**  
   見つかった不足を、元の設計書に反映します。設計書を最新の状態に保つための更新です。[file:62]

6. **`/split-rfc-to-children`**  
   大きすぎる設計書を、扱いやすい小さな単位に分けます。大規模な仕事を整理するときに使います。[file:62]

7. **`/drill-rfc-down`**  
   既存の設計書に質問を重ねて、考慮漏れや設計の穴を埋めます。[file:62]

8. **`/check-final`**  
   最後に、「不足が残っていないか」「全チケットが終わっているか」を確認し、完了を判断します。[file:62]

外側ループでやることは、**話し合う、決める、書く、見直す**ことです。ここにはビジネス側や現場のメンバーも参加できます。[file:63]

## 内側ループ

内側ループは、**夜にAIが自動で回す実装のループ**です。[file:62]
`conver.js` が Tickets.json を読み、決まった順番でチケットを処理します。[file:62]

主な流れは次の通りです。

1. **`make` / `/make-ticket`**  
   チケットの内容を読み取り、何を作るかをAIが理解します。[file:62]

2. **`plan` / `/plan-ticket`**  
   実装の手順を決めます。どのファイルをどう変えるかを整理する段階です。[file:62][file:63]

3. **`start` / `/start-ticket`**  
   実際にコードを書き、必要な修正を行います。[file:62][file:63]

4. **`review` / `/review-ticket`**  
   自分で確認し、ミスや抜けを探して直します。[file:62][file:63]

5. **`resolve` / `/resolve-ticket`**  
   チケットを完了として整理し、警告や残課題も片付けます。[file:62][file:63]

6. **`find` / `/find-omissions-for-next-rfc`**  
   設計書と実装を比べて、まだ足りない部分やズレを見つけます。これは翌日の外側ループの材料になります。[file:62][file:63]

こうして、夜のあいだにAIが静かに実装を進め、翌朝には「できたコード」と「まだ足りない点」がそろいます。[file:63][file:62]

## 昼と夜の役割分担

### 昼の仕事（人間）

- 現場やビジネスの要望を聞く。[file:63]
- 仕様や設計をまとめる。[file:63][file:62]
- AIに任せるタスクをチケットに分ける。[file:63][file:62]
- 夜の成果を見て、次に何を直すか決める。[file:63][file:62]

### 夜の仕事（AI）

- 昼に決まった仕様とチケットを読む。[file:63]
- チケットごとに実装・確認・修正を進める。[file:63][file:62]
- 不足や矛盾を見つけ、次の日の設計材料を残す。[file:63][file:62]

## この方法のメリット

Night-Imp-Loop の大きな利点は、人間のチームが日中に**現場の実情や実際のニーズに合わせて、綿密に話し合いながら仕様と設計をまとめられる**ことです。[file:63]
そのうえで、コードを書くという反復的で機械的な部分をAIに任せることで、チーム全体がより創造的な仕事に集中できます。[file:63]

また、この方法ではエンジニアだけでなく、ビジネスサイドの人も日中の会話や設計づくりを通じて、そのまま生産活動に参加できます。[file:63]
その結果、翌朝には前日の議論がコードに反映された状態から、次の判断を始められます。[file:63]
