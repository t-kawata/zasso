## 1. Purpose of this document

The single most important fact: **the `pjsua-native` feature of the siprs crate does not currently compile (69 errors).** PJSIP is the heart of siprs. ## 2. Background

### 2.1 The crate

- `crates/siprs` is a Rust SIP client that wraps PJSUA (PJSIP) through FFI bindings generated by `bindgen`.
- The `pjsua-native` Cargo feature gates the entire PJSIP FFI layer. When disabled, hand-written stub aliases in `src/ffi/bindings.rs` keep the crate compiling, and a deterministic `TestBackend` (activated by the `test-util` feature) substitutes for PJSIP in tests.
- The vendored PJSIP source lives at `vendor/pjsip/` (has `CMakeLists.txt`). Prebuilt headers/libraries live at `vendor/prebuilt/<target-triple>/{include,lib}`. Currently only `vendor/prebuilt/aarch64-apple-darwin/` exists.
- `wrapper.h` is the single bindgen entry point. It includes `<pjsua.h>`, `<pjmedia.h>`, and `<pjmedia-codec/opus.h>`.

## 3. The core blocker: `pjsua-native` does not compile (69 errors)

### 3.1 Reproduction

```bash
# From crates/siprs
cargo check --features pjsua-native
```

Result: **69 compile errors**, 8 warnings. The crate library does not compile with the feature enabled.

### 3.2 Evidence-based error breakdown (verified against the vendored headers)

The errors were inspected and each category was verified against the actual vendored headers under `vendor/prebuilt/aarch64-apple-darwin/include/`. **A naive "expand the bindgen allowlist" fix is NOT sufficient** — several categories require a vendored-PJSIP upgrade or pure code changes.

| # | Error code | Count | Symptom | Verified fact | Required fix |
|---|-----------|-------|---------|---------------|--------------|
| 1 | E0432 / E0425 | 19 | `PJ_SUCCESS` / `PJ_EINVALIDOP` / `PJ_ENOMEM` / `PJ_EBUSY` missing from `bindings` (`src/error/error_design_siperror.rs`, `src/ffi/callback.rs`, `src/ffi/backend_calls.rs`, ...) | `PJ_SUCCESS` is an **enum enumerator** (`pj/types.h:93`, `PJ_SUCCESS=0,`), not a `#define`. Type-allowlist does not emit enum enumerators. | bindgen config: emit enum enumerators as consts / generate the enum |
| 2 | E0425 | — | `PJSUA_CALL_NULL`, `PJ_CRED_DATA_PLAIN_PASSWD` missing | **Absent from the entire vendored tree** (grep over `vendor/` found nothing). Cannot be emitted by allowlist. | Upgrade vendored PJSIP to a version that defines them, OR change the code to use alternatives |
| 3 | E0609 | 7 | `pjsua_config.turn_cfg` / `turn_cfg_use` missing (`src/config/stun_turn_ice_wiring.rs`) | Fields **DO exist** in the header (`pjsua.h:4751` `turn_cfg_use`, `:4757` `turn_cfg`) | Add the full `pjsua_config` struct to the bindgen type allowlist |
| 4 | E0609 | — | `pjsua_codec_info.encoding_name` / `clock_rate` missing (`src/config/observability_metrics.rs`) | Vendored `pjsua_codec_info` (`pjsua.h:8155`) has only `codec_id` and `priority` — **these fields do not exist in this PJSIP version** | Upgrade vendored PJSIP, OR rewrite the code to derive the codec name/rate from `codec_id` |
| 5 | E0599 | 28 | `pjsip_inv_state::CALLING` etc. — "no associated function or constant named ... for type `u32`" (`src/state/m20_callstate_mapping.rs`) | bindgen generated `pjsip_inv_state` as a `u32` type alias; the C enum (`pjsip-ua/sip_inv.h:87-96`) exists but is not generated as an enum | bindgen config (`prepend_enum_name(false)` etc.) to generate the enum, OR change the code to reference the constants correctly |
| 6 | E0433 | 2 | `AccountId` not in scope (`src/runtime/backend.rs:1029,1213`) | Pure Rust code issue inside `#[cfg(feature = "pjsua-native")]` blocks | Add `use crate::model::AccountId;` (pure code fix) |
| 7 | E0308 | 3 | Mismatched types (`src/ffi/backend_calls.rs:366,428,447`) | Code calls `pjsua_codec_set_priority`, `pjsua_conf_add_port`, `pjsua_call_get_conf_port` with signatures that do not match the bindgen-generated ones | Align the Rust call sites with the generated FFI signatures |

### 3.3 Root cause

The bindgen **allowlist** in `src/build/build_script_bindgen.rs` emits a fixed symbol set that is **not aligned** with what the code under `#[cfg(feature = "pjsua-native")]` actually references, AND the vendored PJSIP headers are **missing some symbols the code expects**. The fix is a combination of:

1. bindgen configuration changes (allowlist + enum/const generation),
2. a vendored-PJSIP upgrade (or code changes) for symbols absent from the current headers,
3. pure Rust code fixes (imports, FFI signatures).

The detailed category-by-category fix design is recorded in the **H1 RESIDUE** section of `README.md`.

## 4. The testing gap (why the crate is "unverified at the heart")

### 4.1 What currently runs

- `make test` → `cargo test --features test-util` → **all green (1337 lib tests pass)**. These use the deterministic `TestBackend`, which substitutes for PJSIP.
- These tests are meaningful for the **siprs control-plane logic** (state machines, config validation, error mapping, reactor/command handling, event conversion, audio algorithms, shutdown, backpressure, DTMF timeout contract, etc.). They do NOT verify real PJSIP behavior.

### 4.2 What does NOT run

- `make test-integration` → `docker compose up` + `cargo test --features pjsua-native --test sip_integration` + guaranteed teardown. **This target cannot execute because `pjsua-native` does not build.**
- Consequently, **no real SIP flow has ever been verified against real PJSIP**: no real REGISTER, INVITE, BYE, DTMF, STUN/TURN, or RTP media exchange.
- The **FFI layer is not even compiled**: `src/ffi/backend_calls.rs`, `src/ffi/callback.rs`, `src/ffi/transport_wiring.rs`, `src/ffi/raw_sip_module.rs`, `src/config/stun_turn_ice_wiring.rs`, etc. are all gated behind `pjsua-native`. They have never been type-checked. Beyond the 69 compile errors, runtime bugs are likely to surface once the build is fixed.
- **False confidence**: a green `TestBackend` test does not imply the real SIP flow works. Example: `make_call` on TestBackend only assigns a call id and publishes no events; the real `pjsua_call_make_call` + callback path is unverified.

### 4.3 The required guarantee

Real-PJSIP testing, **run in CI**, must guarantee both:

1. **Protocol level**: correct SIP message exchange through real PJSIP — REGISTER→200, INVITE→180/200, BYE, SIP INFO / RFC 4733 DTMF, STUN binding / TURN allocate / relay candidates via coturn.
2. **Communication level**: RTP media actually flows between two endpoints through the siprs media path (send/receive audio).

This is exactly RFC §43.4 (Layer 4 interop tests), §62.19 / P16-10 (Docker/Asterisk integration base), and the `make test-integration` target. **The crate's Definition of Done (§50 acceptance criteria, §43 test strategy) is currently NOT met.**

## 5. DESIGN POLICY — producer/consumer separation (MANDATORY)

The following design decisions were made in the working session and MUST be respected by all tickets created by `/drill-rfc-down`.

### 5.1 Prebuilt binaries are committed to the git repo

- Prebuilt PJSIP libraries for **Windows, macOS, and Linux** must all be built successfully and **committed to the git repository**.
- **Principle**: after `git clone`, the prebuilt binaries should, by default, already be present at `vendor/prebuilt/<target-triple>/`. A user should be able to `cargo build --features pjsua-native` without performing any additional PJSIP acquisition step.
- This matches RFC §28.1 (search order: prebuilt → system → vendored source) and §44 / P16-10 (prebuilt refresh pipeline).

### 5.2 Consumer: siprs `build.rs` owns the resolution pipeline

At consumer build time, `build.rs` is the single orchestrator. When `--features pjsua-native` is enabled:

1. Detect the target triple from the Rust host (`rustc -vV`).
2. Resolve the library in this strict order:
   1. `vendor/prebuilt/<target>/lib` — if present, emit `rustc-link-search` + `rustc-link-lib` and use `vendor/prebuilt/<target>/include` as the bindgen header root.
   2. Else, a system PJSIP install (`pkg-config` / environment).
   3. Else, build the vendored PJSIP source **in `build.rs` itself** (invoke `cmake` via `std::process::Command`).
   4. Else, **fail the build** (fail-stop; no warning-and-continue).
3. Emit link directives.
4. Run bindgen (`resolve_header_root` → `generate_bindings`).

Current `build.rs` already has `resolve_prebuilt_lib_dir()`, `resolve_header_root()`, and `generate_bindings()`. **Missing** and to be implemented: (a) the vendored-source-build fallback (stage 2.iii), (b) the staging mode for producing prebuilt output, (c) fixing the linked library name to match the staged artifact (`libpjproject.a` / `pjproject.lib`).

### 5.3 Producer: a dedicated, independent prebuilt-build unit

- The **generation** of prebuilt binaries is the responsibility of a **dedicated, minimal Rust tool** — NOT shell scripts, and NOT the siprs crate's own compile. This keeps the library build's success **independent of the siprs crate's compile status** (i.e., independent of the 69-error bindgen problem).
- Recommended shape: a workspace member such as `crates/pjsip-prebuilt` (no dependency on siprs) whose `main.rs`/`build.rs`:
  - Detects the host OS and determines the target set:
    - **macOS host → `[ <host mac target>, x86_64-unknown-linux-gnu (built in a Linux Docker container) ]`** (Docker on macOS runs Linux containers, so Linux libs can be produced on a Mac).
    - **Windows host → `[ x86_64-pc-windows-msvc ]`** (Windows containers cannot run on macOS; MSVC-targeted PJSIP must be built on a real Windows environment).
  - Builds the vendored PJSIP via CMake (host: `std::process::Command`; Linux-from-Mac: a Docker container defined by a committed `Dockerfile`, copying the artifacts out).
  - Stages the result into `vendor/prebuilt/<target>/{include,lib}`.
  - **Fails (non-zero exit / panic) if the library is unobtainable by any method** — no silent fallback.
- **DoD of the producer is independent**: "the library alone builds and stages successfully" (verify with e.g. `file`/`nm` for the target format, or a minimal C link test). It must NOT be gated on `cargo build --features pjsua-native` succeeding — that is the consumer side's DoD.

### 5.4 Docker-based real-PJSIP tests are required and CI-run

- The Docker integration test base (`make test-integration`, Asterisk/coturn, guaranteed `docker compose down` teardown) is the mandated mechanism for the §5.4/§4.3 protocol- and communication-level guarantees.
- Tickets must not treat "TestBackend green" as sufficient evidence for any PJSIP-integrated behavior.

### 5.5 The two-ticket structure (parallelizable)

Tickets created by `/drill-rfc-down` for the build problem MUST follow this split:

- **Ticket A — consumer/bindgen alignment**: fix the 69 errors so `cargo build --features pjsua-native` passes (bindgen config + vendored-PJSIP upgrade or code changes + pure code fixes). Evidence and category breakdown: **H1 RESIDUE** in `README.md`. DoD: `cargo build --features pjsua-native` passes; `make test-integration` runs green in CI.
- **Ticket B — producer/prebuilt generation + CI + commit**: the dedicated prebuilt-build tool (§5.3), GitHub Actions OS matrix (`macos-latest` / `ubuntu-latest` / `windows-latest`), stage and commit `vendor/prebuilt/` for all targets. **Independent of Ticket A** — the library build can be green before the crate compiles. DoD: `git clone` on each OS → prebuilt present → (once A lands) `cargo build --features pjsua-native` passes.

Ticket A may proceed first on a single platform that already has a prebuilt (e.g., `aarch64-apple-darwin`). Ticket B can proceed in parallel to produce and commit the missing platform prebuilts.

### 5.6 OS mapping for the producer (as decided)

| Host | Targets produced | Mechanism |
|------|------------------|-----------|
| macOS PC | `aarch64-apple-darwin` / `x86_64-apple-darwin` (host) + `x86_64-unknown-linux-gnu` (and optionally `aarch64-unknown-linux-gnu`) | host build via cmake; Linux via Docker container |
| Windows PC | `x86_64-pc-windows-msvc` | MSVC build via cmake (`-G "Visual Studio 17 2022" -A x64`) |
| Linux PC | `x86_64-unknown-linux-gnu` (etc.) | host build via cmake |
