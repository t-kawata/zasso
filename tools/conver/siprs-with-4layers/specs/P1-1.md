# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

# Target ticket is P1-1: Codec Policy, SRTP, Transport Reconnection & Shutdown Command Routing

## RFC Reference

## Background

### Goal
Implement three independent policy modules within the siprs media/lifecycle layer: (1) two-layer codec selection (explicit vs auto mode) that assigns Opus=255, PCMU=254 when preferred_codecs is empty, (2) SRTP policy with feature-flag gating (Disabled/Optional/Mandatory), and (3) M20 shutdown command routing that permits GetAccountInfo while rejecting ConfConnect/ConfDisconnect during shutdown. Each module is a standalone, testable unit that integrates with existing configuration and reactor infrastructure.

### Purpose
These policies form the core control layer for media configuration and lifecycle management in the M20 extension. Without them: (a) codecs default to PJSIP's built-in ordering instead of Opus-first prioritization, (b) SRTP cannot be controlled via config (always enabled or always disabled), and (c) shutdown behavior for M20 commands is undefined (the reactor would attempt to dispatch media operations during teardown, causing undefined PJSIP behavior). Each policy closes a gap between raw PJSIP capability and intentional application-level control.

### Motivation
P1-1 is the first M20-spec ticket after the P0 infrastructure (P0-1 through P0-6) established the crate foundation. The three nodes (N0041, N0042, N0044) were identified as highest-priority M20 additions because: codec auto-mode is required for every call session, SRTP policy directly affects security posture and cannot default to Mandatory without feature-gating, and shutdown routing prevents reactor crashes during teardown. These are preconditions for P1-2 (Security & Platform) and P1-3 (Audio Pipeline).

### Constraints
1. No FFI dependency: configure_codecs_auto_mode must produce a priority map (pure function) rather than calling pjsua_codec_set_priority directly — the FFI binding is deferred to P2-4. 2. SrtpPolicy validate receives a bool feature_enabled flag rather than using #[cfg(feature = "srtp")] directly in the function body, enabling testability without conditional compilation. 3. ShutdownCommandRouter::classify must be a pure function — no reactor state access, no async, no side effects. 4. No new dependencies beyond the existing crate's Cargo.toml (no random crate for jitter — use deterministic seed based on attempt number).

## Investigation

Investigation evidence gathered from RFC graph (N0041, N0042, N0044, N0040, N0043, N0015) and source code (src/config/m20_codec_auto_mode.rs, src/config/srtp_transport_reconnect.rs, src/error/m20_shutdown_routing.rs, src/config/codec_policy_fallback.rs, src/runtime/command.rs, src/error/error_design_siperror.rs, src/error/m20_runtime_command_error.rs, src/config.rs, src/lib.rs):

1. N0041 (Codec Auto Mode): Two-layer selection — preferred_codecs non-empty = explicit mode, empty = auto mode (Opus=255, PCMU=254). The configure_codecs() function in RFC uses pjsua_codec_set_priority FFI. Parent N0040 defines CodecSelectionPolicy (Ordered/PreferOpusFallbackPcmu) and NegotiatedCodec enum. The CallMediaPreferences struct is defined in N0040 parent but not yet implemented — P1-1 only implements the auto-mode computation, not the full CallMediaPreferences struct.

2. N0042 (SRTP & Transport Reconnection): SrtpPolicy enum (Disabled/Optional/Mandatory) with feature-gating via bool flag (not #[cfg] in function body). ReconnectPolicy with exponential backoff: base_delay * 2^attempt, clamped by max_delay, with jitter_ratio randomization. Transport protocol distinction: UDP stateless (no reconnect), TCP/TLS connection-oriented (reconnect needed). Parent N0015 defines TransportConfig enum with Udp/Tcp/Tls variants. The actual transport lifecycle (create, reconnect, destroy) is in N0015's domain and deferred to P2-4.

3. N0044 (Shutdown Routing): Three M20 RuntimeCommand variants: GetAccountInfo (permitted — read-only), ConfConnect (rejected — media mutation), ConfDisconnect (rejected — media mutation). Pure routing function with no reactor state dependence. Uses SipError::invalid_state("shutting down") from error_design_siperror. Parent N0043 defines the shutdown state machine (idempotent, cancels calls, unregisters, drains audio, destroys). The RuntimeCommand enum is already defined in src/runtime/command.rs (P0-6) with all three variants. The error converters (convert_conf_connect_error, convert_conf_disconnect_error, convert_get_account_info_error) are already implemented in src/error/m20_runtime_command_error.rs (P0-4).

4. Existing source state: All three target files are stubs (pub struct Config {}, pub enum Error {}) with [::STUB::] markers. The files have the Initial Design Artifact header. Module declarations exist in src/config.rs and src/error.rs with pub mod statements. No existing implementations to modify.

5. Key architecture decision: ShutdownCommandRouter is placed in src/error/m20_shutdown_routing.rs (error_policy module per the graph), not in runtime/. This keeps routing logic separate from reactor mechanics. The Reactor's dispatch_command calls classify() and acts on the ShutdownCommandAction result — this is the integration point tested in testIntegration.

## Acceptance Criteria

- Happy path: A SipClient is created with default config (preferred_codecs empty). configure_codecs_auto_mode assigns Opus=255, PCMU=254, others=0. All SrtpPolicy::validate calls with feature enabled pass. During shutdown, GetAccountInfo is permitted and returns AccountInfoSnapshot. ConfConnect and ConfDisconnect are rejected with InvalidState.
- Error case: SrtpPolicy::validate is called with Mandatory when srtp feature flag is disabled — returns Err(InvalidConfig). ShutdownCommandRouter::classify is called with ConfConnect during shutdown — returns Reject(InvalidState) with message containing 'shutting down'.
- Edge case: preferred_codecs contains an explicitly-specified codec but is non-empty — CodecAutoMode::apply produces an empty priority map (auto mode bypassed). preferred_codecs is empty and enumerate_codecs returns an empty list — apply returns Ok(()) with empty map. ReconnectPolicy::next_delay with attempt=0 and base_delay=1s returns exactly 1s (no backoff yet). jitter_ratio=1.0 produces delay in [0, 2*computed] range.

## Invariants

- 【Normal establishment】When preferred_codecs is empty, CodecAutoMode::apply assigns Opus=255, PCMU=254, and all other codecs=0. When preferred_codecs is non-empty, auto mode is bypassed (no priorities changed).
- 【Normal establishment】SrtpPolicy::validate returns Ok(()) when: Disabled (always valid) or Mandatory/Optional with srtp feature enabled.
- 【Normal establishment】During shutdown, ShutdownCommandRouter::classify returns Permit for GetAccountInfo and Reject(InvalidState) for media commands.
- 【On error】SrtpPolicy::validate must never panic or crash — it always returns Result<(), SipError> with InvalidConfig kind for feature violations.
- 【On error】If enumerate_codecs() fails, CodecAutoMode::apply must propagate the error without partial priority assignment.
- 【On error】ReconnectPolicy::new must reject invalid parameters (zero base_delay, out-of-range jitter_ratio) at construction time, never at next_delay call time.
- 【Internal state】ReconnectPolicy fields (base_delay, max_delay, jitter_ratio) are immutable after construction — no setter methods provided.
- 【Internal state】ShutdownCommandRouter has no mutable state — classify() is a pure function of (cmd, is_shutting_down).
- 【Boundary】Codec priority values are u8: Opus=255 (max valid priority), PCMU=254, others=0 (disabled). These exact values are invariants.
- 【Boundary】jitter_ratio must be in [0.0, 1.0] — values outside this range are rejected at construction.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C042 — N0041→N0040

- **Precondition**: Codec policy is defined in ClientConfig — either preferred_codecs non-empty (explicit mode) or empty (auto mode). enumerate_codecs() returns available native codecs from PJSIP.
- **Postcondition**: After configure_codecs_auto_mode(), each codec in the system has a priority assigned: Opus=255, PCMU=254, all others=0. When preferred_codecs is non-empty, auto mode is bypassed and no priorities are changed.

- **Precondition**: Transport configuration is defined (TransportConfig enum with UDP/TCP/TLS variants). SrtpPolicy has one of three values (Disabled/Optional/Mandatory).
- **Postcondition**: SrtpPolicy::validate() returns Ok(()) when: (a) policy is Disabled (feature state irrelevant), or (b) policy is Mandatory/Optional AND srtp feature flag is enabled. Returns Err(InvalidConfig) when Mandatory/Optional AND feature flag is disabled.
- **Invariant**: SrtpPolicy Disabled is universally valid. Mandatory and Optional are gated by #[cfg(feature = "srtp")] — at the API level, the validate function receives a bool feature_enabled flag that enforces this gate.

- **Precondition**: Reactor shutdown sequence has started (is_shutting_down == true). A RuntimeCommand is submitted to the reactor for dispatch.
- **Postcondition**: ShutdownCommandRouter::classify() returns Permit for GetAccountInfo (command is forwarded to execute_get_account_info). Returns Reject(InvalidState) with message containing 'shutting down' for ConfConnect and ConfDisconnect. Returns Reject(InvalidState) for all other commands.
- **Invariant**: GetAccountInfo is always Permitted during shutdown. ConfConnect and ConfDisconnect are always Rejected during shutdown. This classification is invariant per variant — no state or context changes the routing decision during shutdown.

## Boy Scout Rule

Translatability improvements for P1-1 (applied to code touched by this ticket):

1. Function names as verb phrases: apply() for CodecAutoMode (applies auto-mode priorities), validate() for SrtpPolicy (validates policy against feature flag), classify() for ShutdownCommandRouter (classifies command during shutdown), next_delay() for ReconnectPolicy (computes next retry delay). All are imperative verbs describing the action.

2. Variable names as domain concepts: codec_id (not "id" or "codec"), preferred_codecs (not "pc" or "list"), jitter_ratio (not "j" or "r"), native_acc_id (matches existing RuntimeCommand field name), is_shutting_down (boolean flag with is_ prefix per coding standards).

3. One function, one responsibility: CodecAutoMode::apply only computes priority map (no FFI, no state mutation). SrtpPolicy::validate only validates (no side effects). ShutdownCommandRouter::classify only routes (no execution). ReconnectPolicy::next_delay only computes delay (no timer scheduling).

4. Named constants: OPUS_PRIORITY = 255, PCMU_PRIORITY = 254 extracted as constants rather than magic numbers. No hardcoded values in function bodies.

5. No error swallowing: All functions return Result<_, SipError> (not Result<_, ()>). Error messages include diagnostic context (codec_id for FFI errors, policy variant for validation errors, cmd variant for shutdown routing).

6. Existing code left cleaner: The three stub files currently have `pub struct Config {}` and `pub enum Error {}` with generic names and no real content. P1-1 replaces these with properly named types. No additional existing code is touched.

- Exception — CodecAutoMode::apply FFI call to pjsua_codec_set_priority: Reason: The actual FFI binding (pjsua_codec_set_priority) is not available until P2-4 when the FFI layer is built. This is not a design defect — the pure function design intentionally separates computation from side effects so that the priority mapping is testable now and the FFI binding can be added later as a thin integration layer.
