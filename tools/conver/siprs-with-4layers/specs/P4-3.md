# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

## Background

### Goal
Implement the complete shutdown orchestration (N0043), media bridge with lock-free RT/async boundary (N0049), HTTP/WS API protocol definition (N0062), and SQLite persistence schema with SeaORM (N0064). These four nodes form the operational layer that enables the siprs crate to shutdown cleanly, bridge audio between the async worker and PJSUA conference bridge, expose a REST/WS API, and persist account configuration.

### Purpose
These four capabilities share the characteristic of being operational infrastructure that the server-mode crate depends on: (1) Shutdown sequences must be safe, idempotent, and cancellation-tolerant; (2) Media bridge isolates RT callback constraints from async audio processing; (3) HTTP/WS protocol provides the wire format for frontend-to-backend communication; (4) SQLite persistence ensures account configs survive restarts and migration management follows best practices.

### Motivation
P3-3 introduced the standalone server entry point but left shutdown as a stub (pub enum State {} in shutdown_specification.rs). The media bridge is required before audio can flow between PJSUA conference and AudioMixer (P5-2). The HTTP/WS protocol constants and AudioFrameHeader are partially implemented (P2-3), but the full protocol spec (text frame format, WebSocket handlers, Axum router integration) is missing. SQLite persistence patterns exist in DatabasePool but need SeaORM entity definitions and migrations.

### Constraints
1. Shutdown atomic swap must use AtomicBool with SeqCst ordering — weaker ordering may skip the second caller check. 2. RustMediaPort callbacks (get_frame/put_frame) run on PJSUA RT thread — no mutex, allocation, or async allowed in these paths. 3. crossbeam::ArrayQueue capacity must be fixed at construction time — no dynamic resizing. 4. HTTP/WS protocol endpoints follow the path constants already defined in http_ws_protocol.rs — no renaming existing constants. 5. SQLite must use rusqlite bundled feature (no system libsqlite3 dependency) — already established in Cargo.toml via sea-orm/sqlx-sqlite.

## Acceptance Criteria

- [Happy path — Complete shutdown sequence] SipClient initialized with 2 accounts and 1 active call. Caller invokes shutdown(). Sequence proceeds: is_shutdown_started -> true, ShutdownCommandRouter rejects new commands, active call receives BYE, accounts are unregistered, audio_worker is drained, backend.shutdown() is called, reactor exits. All return values are Ok(()). Second shutdown() call returns Ok(()) immediately. All invariants satisfied.
- [Error case — Shutdown with ongoing calls timeout] 1 active call does not respond to BYE within 5-second timeout. ShutdownSpec logs the timeout, proceeds to next phase (unregister/drain/destroy) without waiting. The call_map entry is cleaned up after timeout. The overall shutdown still completes with Ok(()).
- [Edge case — Media bridge queue overflow during active call] Under heavy network jitter, the AudioBridge from_rt queue fills to capacity. put_frame on the RT callback drops the overflow frame silently. Subsequent frames continue to be accepted. AudioMixer on the async side continues processing. No panic, lock, or memory allocation occurs on the RT path.

## Invariants

- [Normal condition — Pre-shutdown integrity] Before shutdown() is called, the reactor must be in the Running state and all internal data structures (call_map, account_map, audio_worker) must be consistent. The is_shutdown_started AtomicBool must be false.
- [Error invariant — Partial shutdown recovery] If a phase of the shutdown sequence fails (e.g., pjsua_destroy returns error), the ShutdownSpec must still complete remaining cleanup phases. No call or resource is left in an inconsistent state. Errors are logged but do not abort the sequence.
- [Internal state invariant — atomic guard] Once is_shutdown_started is set to true by the first shutdown() call, it must never be reset to false. All subsequent shutdown() calls must observe true and return Ok(()) immediately.
- [Boundary invariant — Queue capacity] AudioBridge to_rt and from_rt queues must be pre-allocated with sufficient capacity for worst-case latency: minimum 4 frames (80ms @ 20ms frame). Overflow must not block the RT callback — overflowed frames are dropped silently.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C044 — N0043→N0001

- **Precondition**: SipClient has been initialized (initialize() completed successfully); reactor is running and accepting commands
- **Postcondition**: ShutdownSpec orchestrates idempotent shutdown: (1) atomic is_shutdown_started swap prevents re-entry, (2) all active calls are BYE/CANCELed, (3) accounts unregistered, (4) audio worker drained, (5) backend.shutdown() called, (6) reactor loop exits
- **Invariant**: Shutdown is idempotent: first call executes full sequence and returns Ok(()); second and subsequent calls return Ok(()) immediately without executing the sequence again

### C045 — N0044→N0043 (inbound)

- **Precondition**: ShutdownSpec.is_shutdown_started() returns true after first atomic swap
- **Postcondition**: ShutdownCommandRouter.classify() correctly routes commands during shutdown: GetAccountInfo → Permit, ConfConnect/ConfDisconnect → Reject(InvalidState), all others → Reject(InvalidState). Reactor applies this routing before command execution.
- **Invariant**: GetAccountInfo is always Permitted during shutdown (read-only state check). ConfConnect and ConfDisconnect are always Rejected during shutdown (media mutation is unsafe during teardown).

### C050 — N0049→N0033

- **Precondition**: AudioMixer (N0033) is initialized and producing mixed output frames; crossbeam::ArrayQueue capacity is configured
- **Postcondition**: AudioBridge connects AudioMixer (async worker side) to RustMediaPort (RT callback side) via two lock-free crossbeam::ArrayQueue instances. get_frame pulls from rx_queue on RT thread; put_frame pushes to tx_queue on RT thread.
- **Invariant**: Lock-free queues (crossbeam::ArrayQueue) separate the RT callback thread from the async AudioWorkerTask. No mutex, allocation, or await call occurs on the RT callback path. Queue overflow drops frames silently (latest-priority), never blocks.

### C063 — N0062→N0061

- **Precondition**: Standalone server mode (N0061) is configured and running; Axum router is built with shared AppState
- **Postcondition**: HTTP/WS protocol defines 18 REST API endpoints, 2 WebSocket endpoints (control+audio, audio-only), JSON text frame format (type/seq/payload), and binary audio frame format (AudioFrameHeader + PCM data). Axum router registers all routes.
- **Invariant**: Event-audio correlation via sequence numbers: SipEvent.meta.seq and AudioChunkPair.first_seq/last_seq share the same monotonically increasing global counter domain. A consumer can correlate seq=N event with first_seq=N audio chunk.

### C064 — N0063→N0062 (inbound)

- **Precondition**: HTTP/WS API protocol (N0062) defines the endpoints and message formats
- **Postcondition**: JWT auth model (N0063) provides Axum middleware layer that validates Bearer tokens on all protected endpoints. Auth endpoint /api/v1/auth/token issues JWT on valid SIP credentials.
- **Invariant**: Default auth mode is LocalhostOnly: when no JWT secret is configured, only localhost connections are accepted. When JWT secret is configured, all non-localhost connections require valid Bearer token.

### C065 — N0064→N0061

- **Precondition**: Standalone server mode (N0061) is configured; SQLite database path is specified in config
- **Postcondition**: SQLite schema with 4 tables (accounts, transport_configs, client_settings, tls_configs) is created at startup. SeaORM migration files are generated. Makefile targets for migration management (gen-migration, migrate-up, migrate-fresh, gen-entities) are available.
- **Invariant**: rusqlite bundled feature ensures SQLite builds without system library dependency. DatabasePool uses single connection (SQLite file-locked for writes) with busy timeout to avoid database is locked errors.

## Notes

- [Implementation steps] Order of implementation: (1) Replace shutdown_specification.rs stub with ShutdownSpec — testable in isolation via AtomicBool + phase list; (2) Implement media_bridge.rs (RustMediaPort + AudioBridge) with ArrayQueue — testable without PJSUA; (3) Add WsTextFrame, WsBinaryFrame, SequenceGenerator to http_ws_protocol.rs — pure data types; (4) Add init_schema() and SeaORM-compatible entities to sqlite_schema.rs; (5) Wire ShutdownSpec into reactor dispatch loop — integration test with MockBackend.
- [Risks] (1) RustMediaPort requires unsafe FFI extern C callbacks — must document all SAFETY invariants explicitly. (2) crossbeam::ArrayQueue capacity sizing: too small causes frequent frame drops, too large wastes memory. Default to 8 frames (160ms @ 20ms). (3) SequenceGenerator wrap at u64::MAX — theoretically possible but practically negligible.
- [Caveats] (1) AudioFrameHeader was spec-corrected from 24 to 30 bytes in P2-3 — new WsBinaryFrame must use the 30-byte header, not the RFC's 24-byte spec. (2) SeaORM entity generation via sea-orm-cli is not done in this ticket — manual definitions matching the SQLite schema are preferred for library crate simplicity.
- [Open items] (1) Shutdown timeout value per phase should be configurable — decide on default (5s) and whether to expose via ClientConfig. (2) AudioBridge queue capacity should be configurable vs fixed — decide minimum viable default (8 frames).
- [Future improvements] (1) Replace shutdown phase timeout with graceful per-call timeout with progress events emitted via EventBus. (2) Add queue depth metrics export to /api/v1/health for monitoring. (3) Add SeaORM migration CLI integration via Makefile targets in siprs-server crate.
