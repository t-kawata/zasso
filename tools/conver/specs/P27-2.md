# P27-2: conver resumes an unfinished find instead of halting on remanded

## Goal

When the package loop meets a `remanded` ticket, conver sends the stop-format Slack notice, sends a separate unfinished-find notice, re-runs `/find-omissions` with the package graph path and a fixed English directive, and continues the normal loop.

## Purpose

`remanded` is a state owned by the find stage, not a ticket state the per-ticket command table can advance. Treating it as unknown converts a recoverable interrupted run into a dead end.

## Motivation

`crystal-adapter-observer` stopped on `P0-1 remanded` after being run through conver. The package was recoverable: six tickets were `reviewed`, the boundary held no completed find, and nothing else was inconsistent. Recovery had to be done by hand.

## Constraints

- No project-specific branches anywhere in code, tests, or messages.
- Two Slack messages, in order: stop-format, then unfinished-find.
- Every find invocation carries the package's graph path.
- The fixed directive follows the graph path only in resume mode.
- Unknown status still stops; `--no-find` still stops; the find-round limit still applies.
- Slack failure never stops the loop.

## Scope

- `src/runner.ts`: route `remanded` into a resume; detect before every find; build the command; persist the boundary; continue.
- `src/notifier.ts`: separate unfinished-find notice.
- `src/runner.test.ts`, `src/notifier.test.ts`: red-first tests.
- Reuse `getGraphPathFromTickets` in `src/tickets.ts`; it already resolves the path and was unused.

## Contracts → testable form

| Contract | Input schema | Output assertion | Invariant predicate |
|---|---|---|---|
| C001 remanded recovery | terminal set plus one `remanded`, `noFind=false`, detector says unfinished | stop-format send, unfinished send, find invocation with graph + directive, boundary completion, loop continues | never asks the human; no name branch |
| C002 graph path | `metadata.resolvedPaths.graphPath`, else `metadata.source` derivation, else Tickets.json | every find command contains the absolute path; directive only on resume | find never runs without a graph |
| C003 second notice | configured webhook | a separate send with workspace and package before find | delivery failure is non-fatal |
| C004 evidence gate | detector clean OR status not remanded OR `--no-find` OR round limit | existing stop, zero find invocations | recovery requires positive evidence |

## Acceptance criteria

- One stop-format notice plus one unfinished notice, then exactly one resume invocation.
- The invocation contains the absolute graph path and the fixed directive.
- After the resumed find adds a `todo` ticket, the next four commands are make, plan, start, review for that ticket.
- A boundary `IN_PROGRESS` with terminal tickets resumes without the stop-format notice.
- Unknown status, clean detector, `--no-find`, and the round limit each stop without a find.
- Tests use neutral workspace and package names.

## Invariants

- The resumed find counts against `MAX_FIND_ROUNDS`.
- The stop-format message is an alert even when the loop continues; it is sent exactly once per detection.
- If the detector says clean, the loop throws `LoopStoppedError` without re-sending the notice.

## Test plan

- `src/notifier.test.ts`: message builder with and without a ticket key.
- Affected set: `node --experimental-test-module-mocks --test dist/runner.test.js dist/notifier.test.js`, plus `npx tsc --noEmit`.
