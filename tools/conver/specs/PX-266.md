# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

# Target ticket is PX-266: Let the entries census be authored in the specification's own coordinates, so it can be supplied without knowing the ids the reading generates

**Ticket Key**: PX-266 · **Phase**: -1

---

## Background

- 【Goal】Let the entries census be authored in the specification's own coordinates, so that a project can supply one without knowing the identifiers the reading will generate.
- 【Purpose】The sequences axis has exactly one route to being stated: a borrowed census for the role entries, chosen by CENSUS_ROLE_BY_AXIS and counted by denominatorOf. gapsIn reports every axis whose source is unstated and the verdict withholds the guarantee while one stands, so the axis is not optional — without an entries census check-obligation-coverage.js can never exit 0 and the distribution gate at STEP 8 of the grill command can never be satisfied.
- 【Motivation】Measured on ~/shyme/gaia there is no entries census. The one candidate, supplied/sequence-manifest.jsonl, carries 485 identifiers of the form E-civic-proposer-unavailable while the artifact's entries carry identifiers of the form G-1, A-731 and R-6079: the namespaces do not intersect and the agreement check refuses in both directions, so pinning it would refuse hundreds of times rather than state anything. The obstacle is the coordinate, not the document: the census must name the entries by identifiers chosen inside the run, after the material is filed, which no independently authored document can know. The specification, by contrast, carries coordinates that are facts about it rather than about the rail — its line numbers — and a census written as spans over the specification can be authored from the document alone and then held against a reading by containment, which is what makes it external.
- 【Constraints】The change must not weaken the identifier form, which the repository's own fixture relies on and which PX-248's contract fixes; it must not let the axis be stated by a census that covers nothing, which would trade a missing denominator for a vacuous one; and it must name no project — the coordinate is 'a span of the specification', not 'gaia's regions'.

## Investigation

Measured, not inferred. (1) The axis and its single route: obligation-denominator.mjs declares DENOMINATOR_AXES as operations, sequences, boundaries and surfaces, maps the sequences axis to the entries role through CENSUS_ROLE_BY_AXIS, and builds it with a local censusOf that returns unstated when no census is borrowed and census when one is — so for this axis the borrowed census is the only route. (2) What withholds the guarantee: gapsIn returns every axis whose source is 'unstated', filtered only by the axes whose statement and placement are the same act (surfaces alone); measureCoverage sets the verdict to not established when any gap stands. (3) Why an identifier census cannot be supplied for gaia: the artifact's entries carry identifiers of the form G-1, A-731 and R-6079 while supplied/sequence-manifest.jsonl carries 485 identifiers of the form E-civic-proposer-unavailable; the intersection is empty. (4) The check that consumes it: engine.mjs defines every-censused-entry-adjudicated with agreeOn, taking the borrowed census members as the left side and the artifact's sequences whose outcome is neither null nor undefined as the right, keyed by id, and refusing both a censused entry the artifact adjudicates nowhere and an adjudicated entry the census does not name. (5) The coordinates available: blocksFromHeadings builds section identifiers of the form s1, s2 and so on from heading lines, and every entry in declaration.json carries firstLine and lastLine — measured on gaia's declaration, 553 entries and 292 sections, each with a line range — so the specification's line numbers are the coordinate both sides already share. ## Acceptance Criteria

- Happy path: a run whose supplied entries census lists spans of the specification, held against an artifact whose entries cover those lines, completes the agreement check with no refusal; denominatorOf reports the sequences axis as census; and check-obligation-coverage.js reports one unstated denominator rather than two.
- Error case: a census span covering no adjudicated entry is refused by name; an adjudicated entry covered by no censused span is refused by name; a member that is not a well-formed span is refused naming the member; two overlapping spans are refused naming both; and a span outside the specification is refused naming the bound.
- Edge case: the ledger fixture's identifier census agrees exactly as it did before the change with no wording altered in any refusal; and a run carrying no entries census leaves the sequences axis unstated and reported by gapsIn, exactly as before.

## Invariants

- 【Normal establishment】A census entry for the entries role whose selector reads spans of the specification records one member per span, each member being a first and last line inside the specification, and denominatorOf reports the sequences axis as census with that member count.
- 【Invariant on error】A member that is not a well-formed span refuses by name; two spans that overlap refuse naming both; a span whose lines fall outside the specification refuses naming the bound it crossed; and a span covering no adjudicated entry refuses naming the span.
- 【Internal invariant】The correspondence between a censused span and the entries a reading produced is by containment over the specification's line coordinates, so neither side has to name the other; an entry whose members are identifiers keeps the exact-match comparison it had before this change, refused in both directions as it always was.
- 【Boundary invariant】An artifact carrying no entries census leaves the sequences axis unstated and gapsIn reports it; an artifact carrying an identifier census re-derives and agrees exactly as it did before this change, with the ledger fixture unchanged.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C001 — specification coordinates -> entries census

- **Precondition**: A sourceEnumerations entry carries role entries and a selector whose shape reads spans of the specification rather than a field of a supplied document
- **Postcondition**: The entry records one member per span, each carryable as a line range, and the spans are read from the supplied document in the shape the selector names

- **Precondition**: An artifact carries entries with firstLine and lastLine, and a borrowed entries census whose members are spans
- **Postcondition**: Each censused span is held against the entries whose spans it covers, and each adjudicated entry is held against the spans that cover it; a span covering no adjudicated entry is refused by name, and an adjudicated entry covered by no censused span is refused by name

- **Postcondition**: The agreement check compares identifiers exactly as it did before, refusing a censused entry the artifact adjudicates nowhere and an adjudicated entry the census does not name
- **Invariant**: A census written in identifiers behaves exactly as it did before this change

- **Precondition**: An artifact carries a borrowed entries census in either coordinate
- **Postcondition**: denominatorOf reports the sequences axis as census with the member count, so gapsIn returns no gap for it and the verdict can hold
- **Invariant**: The axis is stated by the presence of the census and not by the size of its member list

### C005 — overlapping or out-of-range spans -> the census

- **Precondition**: A census span names a range that overlaps another span, or a range whose lines fall outside the specification
- **Postcondition**: The overlapping or out-of-range span refuses by name, naming both spans or the bound it crossed
- **Invariant**: No line of the specification is claimed twice by one census and none is claimed outside it

## Boy Scout Rule

Translatability plan for every file touched. Functions: name them by what they answer rather than by what they return — the new reader reads as 'the spans a document lists', and the branch in the agreement check reads as 'the coordinate this census uses'. Variables: replace index-shaped names with domain names (censusCoordinate, spanFirst, spanLast, coveringEntries) so a refusal line can be read aloud as a sentence. One responsibility per function: the predicate that decides which coordinate a census uses lives once and is called by the reader, the agreement check and the denominator, so the three cannot disagree about what a member is — the discipline PX-264 applied to the partition of supplied files and PX-265 to the kinds of entry. Hardcoded values: the shape names and the coordinate names are named constants rather than repeated string literals. Swallowed errors: a malformed span is refused by name rather than dropped, and an empty census is a statement rather than an absence, so neither failure is quiet. Proactive improvement inside the touched code: the command text states which coordinate a census is authored from, so an operator no longer has to infer it from the agreement check.

### Exceptions

- Whether an entries census authored as spans is a faithful reading of the specification cannot be tested by the rail. It is impossible to test because faithfulness is a judgement about the document's relation to the specification's meaning, and no check in this library may make that judgement — the rail holds the artifact to the census and reports the disagreement, which is the division of labour its own comments state. This is not a design defect and not an architectural defect: the rail's contract is over the correspondence, not over the truth of either side. Alternative verification: the correspondence itself is fully covered in both directions, so a census that does not match what the reading produced is always refused by name.
- The live gaia workspace is not testable from inside this repository. It is impossible to test a run over ~/shyme/gaia here because the path is outside the repository and its content is not under version control, so a test would assert on an unversioned workspace. This is not a design defect and not an architectural defect: the item is external data rather than code under change. Alternative verification: a fixture reproduces the shape at repository scale — an entries census in spans and an artifact whose entries cover them — and the assertions live there.
- Which spans a project's entries census should name cannot be tested as a fixed list. It is impossible to test a list the rail deliberately does not hold: naming a project's regions in the rail would make the rail that project's instrument. This is not a design defect and not an architectural defect: the coordinate is the contract and the list is the project's. Alternative verification: the test asserts that any well-formed span is read and any malformed one is refused, which is the rule the authoring rests on.
