# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

- [Purpose] The current S5 checks only 15/84 boundaries and compares facts synthesized from the same contract_registry row; S4/S7 skip assigned-only operations and obligation-only sequences; notASequence has no ground; S3 normalization silences transition findings. The next gaia run must surface these gaps instead of returning 0 findings.
- [Motivation] The audit of ~/shyme/gaia showed that the pass was not proof of contract completeness: 300 authored prose contracts were replaced, 185/300 steps have zero boundary facts, 69 boundaries are never meshed, 18 active operations are assigned-only, 5 drawn sequences are obligation-only, 434 notASequence regions have no ground, and 201 inquest Yes answers are outside the gate. PX-283 makes these visible; PX-284 makes them enforced and falsifiable.
- [Constraints] Change only ~/shyme/zasso/tools/conver; never edit ~/shyme/gaia. The new checks must be deterministic and testable with fixtures, not with gaia data. No new dependency, no unwrap-style silent catch, no hardcoded path. The command's residual guarantee language remains. The next /smooth-sequences run on gaia after both tickets must not short-circuit to pass.

## Scope

- Register every new sub-check in .claude/scripts/smooth-sequences/lib/check-registry.mjs from PX-283 so checks.subChecks reports executed or skipped with a reason.
- S5 boundary coverage: collect every boundary named by an active operation's boundary_effects and every boundary: fact id; require a step contract.crosses or a boundary ground; emit S5.boundary-uncovered naming the boundary and the operation.
- S5 projection/authored separation: read contract_prose (PX-283) and contract.authored {pre, post, consumes, produces, errors}; emit S5.projection-only when a step has only a registry projection; never claim a projection-only step is meshed.
- S5 error-set agreement: remove the providerErrors.size === 0 skip in checkConsumerContracts; emit S5.error-set-mismatch when a consumer expects a boundary error the provider does not declare.
- S4 contribution completeness: check every active operation reachable through ownedOperationUnits or obligationUnits, including assigns-only operations; emit S4.contribution-unowned when registry_contribution or the distribution-ledger row is missing.
- S7 obligation-unit validation: validate obligationUnits subjects that name a sequence or operation; emit S7.obligation-unit-unknown when the artifact does not declare the subject.
- S1 notASequence ground: require a non-empty ground, reason, grounding.classification, or external ground reference for every notASequence region; predicateLimb none-applies alone is insufficient; emit S1.not-a-sequence-ground-missing.
- S3 status terminality: stop normalizeStatusGraph from silently adding a transition target as a terminal status; require an explicit status_terminality_ground or emit S3.transition-target-unknown.
- S6 boundary-effect drift: emit S6.boundary-effect-drift when an operation declares a boundary_effect that none of its steps crosses and no ground covers.
- Make the new checks enforced by default; --audit from PX-283 reports every finding with exit 0 and wouldExit; without --audit, findings exit 1.
- Add fixtures modeled on the gaia counts without containing gaia data: 84 boundaries, 15 crossed, 69 boundary_effects-only; 18 assigned-only active operations; 5 obligation-only drawn sequences; 434 notASequence without grounds; 9 normalized statuses; projection-only contracts.
- Update .claude/commands/smooth-sequences.md Appendix A/C to name the new check ids, the ground escapes, the audit/enforce distinction, and the residual guarantees.
- Add unit and integration tests for every new finding and for the no-finding case; assert that the gaia-shaped fixture is red in enforce mode and observable in audit mode.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C001 — design: every declared boundary effect is checked or grounded

- **Precondition**: An active operation declares boundary_effects for a boundary, no step declares contract.crosses for it, and no boundary ground exists.
- **Postcondition**: The detector emits S5.boundary-uncovered naming the boundary and the operation.
- **Invariant**: A non-empty boundary ground suppresses the finding; an uncovered boundary is never silently skipped.

### C002 — design: a registry projection is not an authored contract

- **Precondition**: A v3 step carries only a registry projection and no authored contract facts or contract_prose.
- **Postcondition**: The detector emits S5.projection-only and does not claim the step is meshed.
- **Invariant**: A projection-only contract never produces a meshing verdict.

### C003 — design: notASequence requires a ground

- **Precondition**: A notASequence region carries predicateLimb none-applies and no ground.
- **Postcondition**: The detector emits S1.not-a-sequence-ground-missing.
- **Invariant**: A non-empty ground or grounding.classification suppresses the finding.

### C004 — design: ownership route does not excuse contribution

- **Precondition**: An active operation is reachable only through obligationUnits and not ownedOperationUnits.
- **Postcondition**: The detector checks its registry_contribution and distribution-ledger row.
- **Invariant**: No active operation is skipped because of its ownership route.

## Changes in Prior Implementation Rounds

| Before | After | Description |
|--------|-------|-------------|
| S5 meshed only the boundaries a step declared in contract.crosses | S5 checks every tree boundary; a boundary with no crossing step and no boundary_grounds entry is S5.boundary-uncovered | Check every declared boundary effect, not only the crossed subset. |
| S5 compared typed facts synthesized from the same contract registry | S5 reads contract.authored; a step with neither authored facts nor contract_prose is S5.projection-only and is never meshed | Separate an authored contract from a registry projection. |
| S5 skipped the error-set comparison when the provider declared no boundary errors | S5 compares the consumer error set even when the provider set is empty | Remove the providerErrors.size === 0 escape. |
| S4 contribution iterated ownedOperationUnits only | S4 merges owned and obligation operation units; an assigned-only operation without a contribution or ledger row is S4.contribution-unowned | Check every active operation regardless of its ownership route. |
| S7 validated owned and cross-boundary units only | S7 validates obligationUnits operation/sequence subjects and emits S7.obligation-unit-unknown | Validate the obligation surface that carries assigned units. |
| S1 treated predicateLimb none-applies as a complete notASequence ruling | S1 requires ground, reason, grounding.classification, or ground_ref and emits S1.not-a-sequence-ground-missing | Require a ground for every negative sequence ruling. |
| normalizeStatusGraph added every missing transition target as a terminal status | the migration closes a target only when status_terminality_ground states it is terminal; otherwise S3.transition-target-unknown remains | Stop the migration from silently inventing terminal statuses. |
| S6 had no boundary-effect drift check | S6 emits S6.boundary-effect-drift when an operation effect has no matching step crossing and no boundary_grounds entry | Make an operation-to-step boundary effect mismatch a danger. |
| the repair route table had no entries for the new check ids | S1.not-a-sequence-ground-missing, S4.contribution-unowned, S5.boundary-uncovered, S5.projection-only, S6.boundary-effect-drift and S7.obligation-unit-unknown each have a route | Keep every emitted check id repairable and the route table exhaustive. |
| the clean fixture had only registry-projected steps and no obligation or ground fixtures | the fixture carries contract.authored; projection-only, notASequence-ground, assigned-only, status-ground, drift and gaia-shaped fixtures are added | Prove each new check fires on a fixture and stays quiet on the grounded one. |
| Appendix A described the pre-PX-284 check families | Appendix A names boundary coverage, projection-only, assigned-only contribution, obligation-unit validation, notASequence ground and boundary-effect drift | Keep the operating contract aligned with the enforced checks. |
