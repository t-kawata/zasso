# Implementation Order (TDD Red-Green-Refactor)

Implementation must strictly follow the **Red → Green → Refactor** sequence. Skipping steps, reordering, or parallel execution is prohibited.

## 1. Red — Fully Implement Failing Tests

Before writing a single line of implementation code, write a failing test suite that achieves 100% coverage of the spec's **Goal, Purpose, Motivation, Constraints, Scope, Acceptance Criteria, and Invariants**. Coverage of these seven elements is mandatory; partial implementation is not acceptable.

When the ticket defines **Contracts** (Precondition/Postcondition/Invariant from graph edge annotation), the Red phase must first translate each Contract into testable form — input schemas, output assertions, and invariant predicates — before implementing them as concrete test code. A Contract whose Precondition/Postcondition/Invariant cannot be expressed as a testable assertion is not yet fully specified.

- Tests must cover all observable behaviors, edge cases, failure modes, and invariants. Any behavior not covered is considered undefined and fails review.
- If a feature is deterministic yet fundamentally untestable, this is not a testing gap but an architectural defect. Redesign the system until it is testable before proceeding to implementation.
- Confirm that all tests fail red due to the absence of implementation. Tests that pass green by accident (e.g., meaningless assertions) are invalid.

## 2. Green — Implement Behavior (No Stubs, No Test Modification)

Implement the **behavior** specified by the tests; do not treat passing the tests as an end in itself. Tests are a means of verifying correctness, not the goal itself.

- Implementations that merely satisfy the literal wording of tests—via hardcoding, input-specific branching, or stubbed return values—are prohibited. The implementation must be a generalized, correct solution.
- If it is impossible to distinguish, via testing, whether an implementation is genuine or a disguised green, this indicates a design flaw caused by insufficient coverage. Add tests until the distinction is possible before proceeding with implementation.
- Modifying, deleting, or weakening tests to make an implementation pass is strictly forbidden. The implementation must conform to the tests; the reverse is never acceptable.
- An implementation whose correctness cannot be proven is invalid. It is not considered complete until it (or its design) is restructured into a provably correct form.

## 3. Refactor — Apply the Boy Scout Rule (Green State Only)

Refactor only after all tests are green. Refactoring in a red state is prohibited.

- Apply the Boy Scout Rule (leave the code cleaner than you found it; readability = translatability) to eliminate `unwrap()` calls, hardcoded values, false comments, and untested code in anything you touch.
- Verify that all tests remain green before and after each refactoring step. If a refactor breaks green, roll it back immediately.

## Definition of Done

Implementation is considered incomplete unless all of the following are satisfied:

- The tests fully and precisely specify the intended behavior.
- The implementation passes all tests green, without exception.
- Correctness is empirically guaranteed by the tests (not a disguised green).
- No gap exists between test coverage and intended behavior.

Green without red, green achieved by modifying tests, and green achieved through stubs are all violations and constitute incomplete work.

## Background

PX-285 made the gate total (every declared check is executed or blocked), monotone (a finding whose evidence disappears becomes S.evidence-withdrawn), and honest (pass only when every required authored surface was measured). It did not make the gate closable.

Evidence from the source and from a gaia-shaped workspace:
- educe writes schema 2: rail/artifact.mjs:62 reads schema_version from artifact-schema.json, whose value is 2. No phase writes schema 3.
- migrate-v3 is the only producer of typed contracts, registry_contribution and boundary_effects. It records whole surfaces in migration.synthesized_surfaces (lib/migrate-v3.mjs:326-332), and check-status.mjs:285 refuses a migration-origin surface for every check that claims the specification.
- contract.authored and boundary_grounds have no producer anywhere in the repository; they are read by checks-layer-b.mjs and surfaces.mjs only.
- S5.crossing-side-missing ignores boundary_grounds (checks-layer-b.mjs:211-219), so a ground cannot close a one-sided crossing.
- The unproven verdict line recommends a waiver (report.mjs:286), but a waiver cannot clear a blocked surface (commands/smooth-sequences.md:110,297). The printed next action is a no-op.
- migrate-v3 applies annotations only to a v2 artifact; on a v3 artifact it returns early (lib/migrate-v3.mjs:267) and the CLI applies only the loop/retry annotation field (migrate-v3.mjs:60-74). Incremental authoring is impossible today.

Measured on the real gaia workspace: 84 declared boundaries; operations on both sides 29, provider only 18, consumer only 11, neither 26; 300 v2 steps with 0 typed contracts; 201 Yes readings over 146 subjects.

This ticket makes the gate closable generically. It adds an authoring producer with source citations, distinguishes authored from synthesized evidence per surface and field, makes a ground cover both boundary checks, and replaces the no-op waiver recommendation with the producer command. It does not optimize the gate for gaia and does not change the regeneration transaction; PX-287 owns that boundary.

## Acceptance Criteria

- [Happy path] A v2 fixture with complete cited annotations runs enforce and exits 0 with verdict pass, blocked empty, findings empty and zero readings.
- [Error case] The same fixture with one of two steps annotated exits 4; the blocked reason contains authored 1/2; no spec finding is emitted from the synthesized row; the unproven line names the migrate-v3 producer and does not mention waiver.
- [Edge case] A one-sided crossed boundary with a non-empty cited ground emits neither S5.crossing-side-missing nor S5.boundary-uncovered; an empty ground leaves both findings; a v3 artifact with migration but no provenance exits 4 with unknown provenance.

## Invariants

- [Normal establishment] Every blocked check id has exactly one producer command, and every surface record has an origin of authored, migration or unknown.
- [Invariant on error] An uncited authored fact or ground is refused before it is written; a migration-origin or unknown-origin surface never satisfies a spec-claiming check; a waiver never clears a blocked surface.
- [Internal invariant] For every surface, authored rows plus synthesized rows equal the rows the surface declares; a surface is authored only when synthesized rows are zero.
- [Boundary condition] A v2 artifact still exits 4; a fully annotated v3 fixture exits 0; a partially annotated v3 fixture exits 4 with the authored N/M count; an empty ground suppresses neither boundary check.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C001 — artifact provenance -> surface availability

- **Precondition**: a v3 artifact records migration.authorship for a surface
- **Postcondition**: the surface origin is authored only when every row is authored; otherwise it is migration, and the blocked reason reports authored N/M
- **Invariant**: authored rows plus synthesized rows equal the surface row count, and a synthesized row never satisfies a spec claim

### C002 — annotations document -> migrated artifact

- **Precondition**: a v2 or v3 artifact and an annotations document with cited contracts and grounds
- **Postcondition**: step.contract and step.contract.authored carry the annotated facts, grounds are present, and annotations_digest records the document
- **Invariant**: a second run with the same annotations is byte-identical; a changed document updates only the named rows

### C003 — authored evidence -> citation check

- **Precondition**: an authored fact or boundary ground
- **Postcondition**: the fact cites its step, line and a quote substring; the ground cites the boundary reason code
- **Invariant**: uncited evidence is refused with UNCITED_AUTHORED_FACT or UNCITED_BOUNDARY_GROUND and never reaches the artifact

### C004 — boundary ground -> crossing coverage

- **Precondition**: a declared boundary crossed on one side and a boundary_grounds entry
- **Postcondition**: a non-empty ground suppresses S5.crossing-side-missing and S5.boundary-uncovered for that boundary
- **Invariant**: an empty or whitespace-only ground suppresses neither check

### C005 — blocked surface -> repair route

- **Precondition**: a report with at least one blocked check
- **Postcondition**: every blocked entry carries a producer command and the unproven verdict lists them
- **Invariant**: no blocked surface is cleared by a waiver and no unproven verdict recommends one

### C006 — legacy provenance -> spec claim

- **Precondition**: a v3 artifact with migration but neither authorship nor synthesized_surfaces
- **Postcondition**: every spec-claiming check blocks with origin unknown
- **Invariant**: such an artifact never reaches verdict pass
