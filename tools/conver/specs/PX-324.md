## Background

### Goal

At `/make-ticket`, mechanically output every piece of information needed for an accurate and safe design:

- the sequences and operations this ticket must implement;
- which parts are shared with other tickets and with other crate directories;
- the boundary contracts and their preconditions, postconditions and invariants;
- which units are references the ticket must consume, not reimplement.

Then require the ticket design to use that output.

### Purpose

The distribution data already reaches `Tickets.json` and `show-ticket-context.js --for-spec` renders `## Distribution Obligations`. But `make-ticket.md` never tells the AI to read it, never distinguishes this ticket's work from a shared or foreign part, and never checks that the step and boundary contracts survived into the test plan.

### Motivation

A ticket that implements a shared step without its boundary contract, or reimplements a reference unit, is unsafe even though the producer-side distribution chain is complete. The consumer side must be as mechanical as the producer side.

### Constraints

- Strict TDD; no test modification; additive only; no new dependency.
- The mechanism runs only when sequence/operation/boundary-contract information exists.
- A ticket with no distribution (Case B, or a pre-split ticket) is a skip, never a failure.
- The brief prints only facts present in the ticket, the package view or `Tickets.json`; an unknown owner is printed as unknown, never guessed.
- Verification uses `node --test` on the impact set, not `make test`.

## Investigation

- `show-ticket-context.js:573-640` renders the distribution units, operation obligation, sequence steps and their seven axes. The sequence unit's `obligation.steps` is only this ticket's local steps; the other steps are in the package view and in other tickets.
- `view.mjs:152-176` puts every step of a shared sequence on the `xdir-` unit, so the package view is the source for the full sequence.
- `add-tickets-for-phase.js` populates `distribution.units`; `ticketPrerequisites` (PX-323) records implementation prerequisites.
- `verify-make-contracts.js` checks contracts against `testUnit`, but it does not know whether the distribution units and their step/boundary contracts reached the test plan.
- `make-ticket.md` Step 1's section table omits `## Distribution Obligations`; Step 9 mentions only `## Operation-Boundary Contracts`.

## Acceptance Criteria

- Happy path: a ticket with a shared sequence renders each step's owner (`this ticket`, another ticket key, or a package id), and a ctr unit renders its direction, counterpart and pre/post/invariant; the gate passes when every implement unit is in the test plan and every step/boundary contract is in `ticket.contracts`.
- Error case: an implement unit absent from the test plan is `DISTRIBUTION_UNIT_UNTESTED`; a step contract absent from the ticket is `STEP_CONTRACT_NOT_DELIVERED`; a ctr boundary contract absent is `BOUNDARY_CONTRACT_NOT_DELIVERED`; a reference unit whose provider is named nowhere is `SHARED_WORK_UNDECLARED`.
- Edge case: no distribution → `skipped:no-distribution` exit 0; a ticket from an instant conversation keeps its old shape; an unknown foreign owner prints `unknown package`, not an invented id.

## Invariants

- [Normal establishment] The brief is a projection of the ticket, the package view and `Tickets.json`; it adds no field and invents no owner. Own work, shared work and reference work are distinguished.
- [Error invariant] A missing step contract, a missing boundary contract, an untested implement unit or an undeclared provider is a named failure, never a silent pass.
- [Internal state invariant] Re-rendering the same ticket yields the same brief; the gate is deterministic.
- [Boundary invariant] No distribution → skip, exit 0, no new required field. Case B is unchanged.

## Contracts — mandatory 100% test coverage in TDD Red phase

### C001 — brief:work-share

- **Precondition**: A ticket carries a sequence unit and the package view carries the full sequence.
- **Postcondition**: The brief prints every step with an owner: `this ticket`, another ticket key, or a package id; an unknown owner prints `unknown package`.
- **Invariant**: The brief never invents an owner and never omits a step the view carries.

### C002 — brief:boundary

- **Precondition**: A ticket carries a ctr unit and a matching boundary contract in `ticket.contracts`.
- **Postcondition**: The brief prints the direction, counterpart and the contract's pre/post/invariant.
- **Invariant**: A ctr unit without its contract is visible as missing, not silently blank.

### C003 — gate:delivery

- **Precondition**: A ticket carries distribution units and a test plan.
- **Postcondition**: Every implement-mode unit appears in `testUnit` or `testIntegration`; every local step contract appears in `ticket.contracts`; every ctr boundary contract appears; a reference unit names its provider or implementer ticket.
- **Invariant**: Each failure carries a stable named code.

### C004 — gate:conditional

- **Precondition**: A ticket has no `distribution.units`.
- **Postcondition**: The gate returns `skipped:no-distribution` and exits 0; the command adds no step.
- **Invariant**: Case B and pre-split tickets are unchanged.

### C005 — command:steps

- **Precondition**: `make-ticket.md` is read.
- **Postcondition**: It contains Step 1.5, Step 6 Phase 1.6, Step 7's conditional gate and Step 9's distribution-section requirement, each written as conditional.
- **Invariant**: The steps are no-ops when the distribution is absent.

### C006 — brief:no-invention

- **Precondition**: The package view is unreadable.
- **Postcondition**: The brief still renders the local steps and marks the rest `not available`; it does not invent a package or ticket.
- **Invariant**: Unknown information is printed as unknown.
