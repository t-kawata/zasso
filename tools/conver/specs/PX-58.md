## Background

### Goal
Normalize all file path outputs in JSON to home-directory-relative (~/) format, making them portable across machines without manual repair.

### Purpose
Currently paths stored in GRAPH.json, status JSONs, Dirs-Tree.json, and Tickets.json are either (a) raw relative strings like `RFC-ROOT.md` or (b) absolute paths with hardcoded `/Users/kawata/...`. When the same JSON is used on another machine (different username, different $HOME), absolute paths break and relative paths resolve incorrectly. By storing all paths as `~/...` and expanding on read, the same JSON works on any machine.

### Motivation
Real failure: `RFC-ROOT-GRAPHIFY-Status.json` contains `/Users/shyme/shyme/zasso/crates/siprs/RFC-ROOT.md` — a path from a different user account. This causes pipeline operations to fail silently when run on the current machine. Root cause: scripts use `path.resolve()` which embeds current machine absolute path without post-processing.

### Constraints
- Scope strictly limited to `tools/conver/.claude/` scripts — no changes to command `.md` files or external tooling
- Test code may be placed outside `.claude/` (e.g. tests/ directory)
- No new npm dependencies allowed
- Must use `os.homedir()` from Node.js standard library
