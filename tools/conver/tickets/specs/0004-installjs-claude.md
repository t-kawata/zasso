# install.js による .claude ディレクトリのインストーラ

## Summary

`.claude` ディレクトリ内の全ファイル（commands, scripts, スキーマ等）を任意のターゲットディレクトリにインストールするための `install.js` スクリプトを作成する。インストーラはスクリプト自身の位置から相対的に `.claude` ディレクトリを特定し、ターゲット上の同名ファイルに対してユーザーに確認プロンプトを表示する。

## Background

conver プロジェクトの `.claude` ディレクトリには、開発パイプラインを駆動するスラッシュコマンド群（12ファイル）、チケット管理スクリプト群（28+ファイル）、RFC検証スクリプト群、共通ライブラリなど、合計68ファイルが格納されている。これらの資産を別プロジェクトに導入する際、現在は手動でファイルをコピーする必要があり、以下の問題がある：

- コピー漏れが発生する
- 同名ファイルの上書き判断が煩雑
- 依存関係（lib/ ディレクトリのスクリプトなど）の見落とし

これを解決するため、`.claude` ディレクトリ全体を構造を保ったまま任意のターゲットにインストールする専用スクリプトが必要である。

## Scope

### 含めるもの

- `install.js` の作成（CommonJS, Node.js バージョン18+対応）
- 以下の機能を実装する：
  - スクリプト自身のディレクトリに存在する `.claude` ディレクトリからファイルを読み取り、指定されたターゲットディレクトリにコピー
  - ターゲット側に同名ファイルが存在する場合、1ファイルごとに `y/n` のプロンプト
  - `-y` フラグで全ての上書きを自動承認
  - `-t` / `--target` オプションでターゲットパスを指定
  - ディレクトリ構造を維持したコピー（`mkdir -p` 相当）
  - `.DS_Store` などの不要ファイルの自動スキップ
  - インストール完了サマリーの表示（コピー数・スキップ数・上書き数）

### 含めないもの

- Tauri/Rust のネイティブインストーラとの統合
- インストール後の自動フック実行
- バージョン管理や差分更新（初回リリースでは全量コピーのみ）
- npm パッケージとしての公開
- アンインストール機能

## Investigation

### ディレクトリ構造（調査日: 2026-06-25）

```
.claude/
├── commands/           # 12 ファイル
└── scripts/
    ├── grill-me-for-rfc/   # 9 ファイル
    ├── lib/                # 5 ファイル
    └── tickets/            # 28+ ファイル + 3 JSON スキーマ
        └── review/         # 3 ファイル
```

### 総ファイル数

- インストール対象: 68 ファイル（`.DS_Store` 除く）

### 既存スクリプトの規約

- ランタイム: Node.js >=18
- モジュールシステム: CommonJS（`require` / `module.exports`）
- ファイル命名: **lowercase with hyphens**

### 実装に必要な技術要素

- `fs.cpSync` または `fs.cp`: ディレクトリ構造を維持したコピー
- `fs.existsSync`: ファイル存在確認
- `readline.createInterface`: プロンプト表示とユーザー入力受付
- `path.relative`, `path.resolve`: パス解決
- `process.argv`: コマンドライン引数解析（`-t`, `-y` オプション）
- `__dirname`: スクリプト自身のディレクトリ取得

### 重要な設計判断

- スクリプトの配置場所: プロジェクトルート直下（`install.js`）→ `__dirname` から `./.claude` を参照
- CWD 非依存: `__dirname` で自身の位置を特定するため、どのディレクトリから実行されても正しく動作する
- コピー順序: ディレクトリ構造を再現してからファイルをコピー（深さ優先で再帰的に処理）

## Test Plan

### ユニットテスト計画

`test.sh` に以下のテストを追加する：

1. **正常系: 新規インストール**
   - 空のテンポラリターゲットに `install.js -t <target>` を実行し、全68ファイルが正しいディレクトリ構造でコピーされることを確認
   - コピーされた各ファイルの内容が原本と同一であることを確認（diff 比較）

2. **正常系: 一部ファイル重複時のプロンプト**
   - ターゲット側にあらかじめ一部ファイルを配置
   - `install.js -t <target>` を実行し、該当ファイルに対してプロンプトが表示されることを確認（自動テストでは入力ストリームを `yes` にパイプ）
   - 応答に応じて上書き／スキップが正しく行われることを確認

3. **正常系: `-y` フラグ（全上書き許可）**
   - ターゲット側にあらかじめ全ファイルを配置
   - `install.js -y -t <target>` を実行し、プロンプトなしで全て上書きされることを確認

4. **異常系: ターゲットディレクトリ不在**
   - `-t` で存在しないディレクトリを指定した場合、親ディレクトリを `mkdir -p` 相当で自動生成するか、適切なエラーメッセージを表示する

5. **異常系: `.claude` 不在**
   - `install.js` と同じディレクトリに `.claude` が存在しない場合、適切なエラーメッセージを表示する

6. **異常系: `-t` オプションなし**
   - 必須オプション `-t` を指定しなかった場合、使用方法を表示して終了する

7. **境界値: 空の `.claude` ディレクトリ**
   - `.claude` ディレクトリ自体が空の場合、「コピーするファイルがありません」と表示して正常終了する

8. **CWD 非依存確認**
   - 一時的に別ディレクトリに移動してからスクリプトを実行し、`__dirname` ベースで正しく `.claude` を特定できることを確認

### ユニットテスト不可能な項目（例外）

なし。全てのロジックは `fs` と `readline` の操作で構成され、テンポラリディレクトリを用いてテスト可能である。

## Boy Scout Rule — 翻訳可能性計画

`install.js` は新規ファイルであるため、最初から翻訳可能性を満たす設計とする：

- **関数名は動詞句**: `copyFileWithPrompt()`, `collectFiles()`, `showUsage()`, `parseArgs()`
- **変数名はドメイン概念**: `scriptDir`, `sourceClaudeDir`, `targetDir`, `overwriteAll`
- **一関数一責務**: 引数解析、ファイル収集、プロンプト表示、ファイルコピーは各関数に分割
- **ハードコード値は名前付き定数**: `SOURCE_DIR_NAME = '.claude'`, `EXCLUDE_PATTERNS = ['.DS_Store']`
- **エラー握りつぶし禁止**: ファイル読み取り/書き込みエラーは `try-catch` で捕捉し、適切に exit code で報告
- **早期リターン**: 深いネストを避け、ガード節で早期リターン
