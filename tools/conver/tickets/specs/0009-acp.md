# ACPセッション管理 (session.ts)

## Summary

`src/session.ts` に実装する ACP (Agent Client Protocol) セッション管理モジュール。
`@agentclientprotocol/sdk` を使用して `claude-agent-acp` 子プロセスを起動し、initialize → session/new → prompt → dispose の全ライフサイクルを管理する。現状はスタブ実装（`[::STUB::] P3-1`）であり、本チケットで以下の関数群を本実装する：

- `spawnAgent(apiKey, model)`: `claude-agent-acp` 子プロセス起動 + DeepSeek V4 環境変数注入
- `buildClientApp()`: `ClientApp` 構築 + permission 自動承認ハンドラ設定
- `createSession(cwd, apiKey, model)`: initialize → session/new → `AcpSession` 返却
- `withSession<T>(cwd, apiKey, model, fn)`: `createSession` → fn → `disposeSession` (try/finally)
- `runCommand(acpSession, command, options)`: `prompt` + `nextUpdate` ループ + タイムアウト検出
- `disposeSession(acpSession)`: `session.dispose()` + `proc.kill()`

`AcpSession` インターフェースは `proc` / `stream` / `sessionId` / `ctx` / `session` の5フィールドを持つ。

## Background

conver.js のメインループ（`runner.ts`）は、各チケットの処理を複数の独立した ACP セッションで実行する。ACP プロトコルは JSON-RPC 2.0 ベースで、`claude-agent-acp` バイナリが Claude Code の ACP インターフェースを提供する。

### 4セッション完全分離アーキテクチャ

各チケットは以下の4つの独立したACPセッションで直列処理される：

```
[Session A] make-ticket → plan-ticket → start-ticket
    │ dispose
[Session B] review-ticket
    │ dispose
[Session C] resolve-ticket
    │ dispose
(Session D: find-omissions-for-next-rfc)
    │ dispose
次のチケットへ
```

各セッションは `spawnAgent()` で新しい `claude-agent-acp` プロセスを起動し、`session/new` で新しいセッションIDを発行する。これにより前のチケットのコンテキストが次のチケットに影響を与えない。

### DeepSeek V4 環境変数注入

`spawnAgent()` は子プロセスに以下の環境変数を注入し、DeepSeek V4 の Anthropic 互換エンドポイントを使用する：

| 環境変数 | 値 | 役割 |
|---|---|---|
| `ACP_PERMISSION_MODE` | `bypassPermissions` | 権限確認バイパス |
| `ANTHROPIC_BASE_URL` | `https://api.deepseek.com/anthropic` | APIエンドポイント差し替え |
| `ANTHROPIC_AUTH_TOKEN` | `apiKey` | DeepSeek API キー |
| `ANTHROPIC_MODEL` | `model` | 使用モデル |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` | `deepseek-v4-pro` | Opus相当モデル（固定） |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | `model` | Sonnet相当モデル |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `model` | Haiku相当モデル |
| `CLAUDE_CODE_SUBAGENT_MODEL` | `model` | サブエージェントモデル |
| `CLAUDE_CODE_EFFORT_LEVEL` | `xhigh` | 推論努力レベル |

### 権限ハンドリング（2重の安全策）

1. **環境変数**: `ACP_PERMISSION_MODE=bypassPermissions`
2. **ACPハンドラ**: `.onRequest(session/request_permission)` で `allow_always` を自動選択

2. 全6関数が空実装（常に `Promise.resolve()` または空文字を返す）

## Scope

### AcpSession インターフェースの本実装

```typescript
export interface AcpSession {
  proc: ChildProcess;
  stream: Stream;
  sessionId: string;
  ctx: ClientContext;
  session: ActiveSession;
}
```

- `proc`: `spawn()` で起動した `claude-agent-acp` 子プロセス
- `stream`: `acp.ndJsonStream()` で生成した双方向 JSON-RPC ストリーム
- `sessionId`: `session/new` 応答の ID
- `ctx`: ACP `ClientContext` — セッション構築や agent メソッド呼び出しに使用
- `session`: `ActiveSession` — `prompt()` / `nextUpdate()` / `dispose()` を提供

### spawnAgent(apiKey, model) の実装

- `child_process.spawn('claude-agent-acp', [], { stdio: ['pipe', 'pipe', 'inherit'], env: { ...process.env, ...DeepSeek envs } })`
- 標準入力を `Writable.toWeb(proc.stdin)`、標準出力を `Readable.toWeb(proc.stdout)` で Web Stream に変換
- `acp.ndJsonStream(writable, readable)` で ACP Stream を生成
- `{ proc, stream }` を返す
- エラー時（バイナリ不在等）は `spawn` の例外がそのまま伝播

### buildClientApp() の実装

- `acp.client({ name: 'conver' })` で ClientApp 生成
- `.onRequest(session/request_permission)`: `allow_always` または `allow_once` を自動選択
- `.onNotification(session/update)`: 空ハンドラ（通知を無視）
- ClientApp を返す

### createSession(cwd, apiKey, model) の実装

1. `spawnAgent(apiKey, model)` で子プロセス + ストリーム起動
2. `app.connectWith(stream, async (ctx) => { ... })` で接続
3. `ctx.request(initialize)` でプロトコルバージョン合意
4. `ctx.buildSession(cwd).start()` でセッション開始
5. 30秒の初期化タイムアウト（超過時は `proc.kill()` + reject）
6. `AcpSession` を resolve

### withSession<T>(cwd, apiKey, model, fn) の実装

- `createSession` でセッション生成
- `try { return await fn(session) } finally { disposeSession(session) }`
- 例外発生時も `disposeSession` が必ず実行される

### runCommand(acpSession, command, options) の実装

1. `acpSession.session.prompt(command)` でコマンド送信
2. `nextUpdate()` を無限ループで読み取り
3. `kind === 'stop'` でループ終了、`response` を返す
4. `Date.now()` と `options.timeoutMs` の比較でタイムアウト検出
5. タイムアウト時: `CommandTimeoutError` を throw
6. `options.verbose && msg.kind === 'session_update' && update.sessionUpdate === 'agent_message_chunk'` の場合に `process.stdout.write(update.content.text)` で chunk を出力
7. 空メッセージ（`!msg`）は `continue` でスキップ

### disposeSession(acpSession) の実装

1. `try { session.dispose() } catch { /* 無視 */ }` — dispose エラーは握りつぶす
2. `proc.kill()` で子プロセス終了

## Non-scope

- **エラータイプの追加**: `SessionError` 等の新しいエラー型は本チケットで追加しない（`CommandTimeoutError` のみ使用）
- **セッションの再利用**: 1セッションは1回のコマンド実行で使い捨て。セッションのプーリングや再利用は行わない
- **ACP サーバーモード**: `@agentclientprotocol/sdk` のサーバー機能（`AcpServer`）は使用しない。ClientApp モードのみ
- **ファイルパスの絶対パス変換**: `withSession` に渡す `cwd` は呼び出し元（`runner.ts`）で `path.resolve()` 済みであることを前提とする
- **バイナリ不在のエラーハンドリング**: `claude-agent-acp` が未インストールの場合、`spawn` の ENOENT 例外はそのまま呼び出し元に伝播する

## Boy Scout Rule — 翻訳可能性計画

### 現在のスタブからの改善点

1. **AcpSession インターフェースの拡充**: `sessionId: string` のみから全5フィールド（`proc`, `stream`, `sessionId`, `ctx`, `session`）に拡張 — 各フィールド名が役割を名詞で表現

4. **コメントの「なぜ」記述**: 権限ハンドリングの二重安全策、`disposeSession` でのエラー握りつぶしの理由を日本語で記述
