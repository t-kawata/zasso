# ビルド確認・E2E動作検証

## Summary

P4-3 は conver.js パイプラインの全モジュール実装完了後の統合ビルド確認と E2E 動作検証を行う。
すべてのソースコード（error.ts, cli.ts, tickets.ts, notifier.ts, session.ts, runner.ts, conver.ts）と
対応するテストが実装済みであり、最終確認としてビルド・テスト・CLI 実行の各観点を検証する。

## Background

全7モジュールの実装チケット（P0-1〜P4-2）が完了し、All Green のテスト状態を迎えた。
最終工程として以下を確認する必要がある：

- `npm run build`（tsc）でコンパイルエラーゼロ + `dist/conver.js` 生成
- `make build-conver` の動作
- 全52件のテストが通過すること
- CLI 動作（--help / 必須フラグ欠如）が期待通りであること
- test.sh による tickets スクリプト統合テストの通過

## Scope

1. **ビルド検証**: `npm run build`（tsc）でコンパイルエラーゼロ、`dist/conver.js` が生成される
2. **ビルド抽象化検証**: `make build-conver` が正しく `cd tools/conver && npm run build` を実行する
3. **ユニットテスト完全通過**: 全52テストがエラーなく通過する
4. **CLI 動作検証**:
   - `node dist/conver.js --help` で usage 表示 + exit 0
   - `node dist/conver.js`（必須フラグ欠如）でエラーメッセージ + exit 1
   - `node dist/conver.js -k sk-test`（slack-url 不足）でエラーメッセージ + exit 1
5. **test.sh 統合テスト**: tickets スクリプト全 CRUD 操作が正常に動作する

## Non-scope

- 新たな機能実装やバグ修正は含まない（全モジュールは P0-1〜P4-2 で完了済み）
- ACP 接続を伴う実際の E2E 実行（Slack URL / API Key 実機が必要）は含まない
- パフォーマンス測定や負荷テストは含まない
- 各モジュールの個別ユニットテストの追加は含まない（既存テストで担保済み）

## Test Plan

### ユニットテスト計画

全7モジュールのユニットテストは P0-1〜P4-2 ですでに実装済み（52件／全パス）。
P4-3 では新たなユニットテストは追加せず、既存テストの完全通過をもって代える。

### ユニットテスト不可能な項目（例外）

| 項目 | 理由 | 代替検証手段 |
|------|------|-------------|
| ACP セッションの実接続テスト | 実際の API Key と Slack URL が必要 | モックを使ったユニットテスト（session.test.ts）で代替 |
| Slack 通知の実送信テスト | 実際の Slack Webhook URL が必要 | HTTP モックを使ったユニットテスト（notifier.test.ts）で代替 |
| ビルド成果物の動作確認 | TypeScript コンパイル後でないと実行不可 | E2E テスト（本セクションで定義） |
| test.sh 統合テスト | 多数の外部スクリプト・テンポラリファイルを作成 | E2E テスト（make test 経由） |

## Boy Scout Rule — 翻訳可能性計画

P4-3 はコードを変更せず検証のみを行うチケットであるため、新たな翻訳可能性改善は発生しない。
検証の過程で既存コードの翻訳可能性の問題を発見した場合は、即座に修正すること。

現時点では全モジュールの関数名・変数名は散文として読める状態にあり、責務の混在や
ハードコード値の使用は見られない。

### Makefile の改善

Makefile のデフォルトターゲットが `test` であり、`test.sh` を実行するようになっている。
テスト実行のエントリポイントとして `make test-conver` を推奨する。
必要に応じて Makefile のデフォルトターゲットを `help` または `test-conver` に変更することを検討する。
