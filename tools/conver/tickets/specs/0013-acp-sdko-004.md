# ACP SDK型定義の整合性（O-004）

## Summary

SDK バージョン更新に伴い型名が `acp.NdJsonStream` → `acp.Stream` に変更された。
実装（session.ts）は既に正しい型名に追従しているが、設計文書 RFC_ROOT.md が
古い型名のままである。RFC_ROOT.md の型定義を実装に合わせて更新し、session.ts
に SDK バージョンによる型名の差異を示す注釈コメントを追記する。

## Background

RFC-001（conver.js）の実装過程で、`@agentclientprotocol/sdk` のバージョン更新に
より以下の型名が変更された：

| 旧型名 | 新型名 | 使用箇所 |
|--------|--------|----------|
| `acp.NdJsonStream` | `acp.Stream` | AcpSession.stream フィールド、spawnAgent 戻り値型 |
| `acp.MonadClient` | `acp.ClientApp` | buildClientApp 戻り値型 |

実装（session.ts）は SDK 更新後も正しく動作しており、型名は既に新しいものに
追従している。しかし設計文書 RFC_ROOT.md のコードブロックには古い型名
`acp.NdJsonStream` が残存している。これは RFC と実装の間に乖離があり、
保守者がどちらが正しいかを判断できず混乱する原因となる。

また、session.ts には SDK バージョンによる型名の差異を示す注釈がなく、
将来の SDK 更新時に型名変更の履歴を追跡できない。

## Scope

以下の修正を実施する：

1. **RFC_ROOT.md**（設計文書）: 2箇所の `acp.NdJsonStream` を `acp.Stream` に修正
   - line 235: `AcpSession` インターフェースの `stream` フィールド型
   - line 244: `spawnAgent()` 戻り値型
2. **session.ts**: `spawnAgent()` の戻り値型に `acp.Stream` のアサーションを維持
   （変更不要、既に正しい）
3. **session.ts**: 冒頭に SDK 型名のバージョン差異を示す注釈コメントを追記
4. **テスト**: ビルド・既存テストの通過確認（ソースコードのロジック変更はないため）

## Non-scope

- ソースコードのビジネスロジック変更は行わない
- `acp.MonadClient` はどのソースコードにも存在しないため、文字列の置換は行わない
  （注釈コメント内でのみ言及する）
- その他の RFC_ROOT.md セクションの編集は行わない（§4 の型定義のみが対象）

## Investigation

### 証拠1: RFC_ROOT.md に古い型名が残存

RFC_ROOT.md line 235:
```
  stream: acp.NdJsonStream;
```

RFC_ROOT.md line 244:
```
): { proc: ChildProcess; stream: acp.NdJsonStream } {
```

### 証拠2: session.ts は既に正しい型名を使用

session.ts line 22:
```
  stream: acp.Stream;
```

session.ts line 46:
```
): { proc: ChildProcess; stream: acp.Stream } {
```

session.ts line 79:
```
export function buildClientApp(): acp.ClientApp {
```

### 証拠3: 他のソースファイルに古い型名は存在しない

cli.ts, runner.ts, conver.ts, error.ts, notifier.ts, tickets.ts に
`NdJsonStream` および `MonadClient` の使用箇所はない。

### 証拠4: session.ts に SDK バージョン注釈がない

session.ts の冒頭コメント（lines 1-9）には以下の記述があるのみで、
SDK 型名のバージョン差異に触れていない：

```
// session.ts — ACP セッション管理
// claude-agent-acp の起動から dispose までの全ライフサイクルを管理する。
//
// 権限ハンドリングは二重の安全策を取る：
//   1) 環境変数 ACP_PERMISSION_MODE=bypassPermissions
//   2) onRequest(session/request_permission) ハンドラで allow_always 自動選択
//
// dispose エラーは握りつぶす — セッション破棄の失敗がプロセス全体の停止を
// 引き起こしてはならない。
```

SDK バージョンによる型名の差異を示すコメントの追記が必要である。
